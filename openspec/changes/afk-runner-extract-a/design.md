## Context

Phase A of the extraction (umbrella change `afk-runner-extraction`, design D1/D5/D7 — see its proposal.md for motivation). The facts that shape this phase's approach, re-verified on this branch:

- The closure behind `runAgent` is exactly 18 review-loop files, 2,886 lines (`agent-runner`, `spawn`, `progress-log`, `line-handler`, `backend-select`, `claude-stream`, `event-stream`, `cost`, `run-stats`, `config`, `worktree`, `todo-capture`, `live-format`, `trace-log`, `diff-stats`, `claude-argv`, `agent-command`, `claude-spawn-dir` — the figure holds post-#432), plus `mutation-improve/src/diff-guard.ts` (49 lines, zero imports) for `write-guard.ts`'s `parsePorcelainPaths`. Internal imports of the 18 close over the set; external imports are `node:*` and `zod` only.
- The afk-runner tree touches five original modules across its whole upward surface: `agent-runner.js`, `spawn.js`, `progress-log.js` (types), `claude-argv.js` (`MAX_ARG_STRLEN`, via #432's `agent-config.ts`), `diff-guard.js`. Measured on this branch: 20 src files (23 import statements) and 17 test files (24 statements, `fixtures/fake-pipeline.ts` included) import upward against `review-loop`/`mutation-improve`; a further 7 test files (7 statements — `agent-config`, `cli`, `config`, `mcp-servers`, `work/fix-target`, `work/implement`, `work/verify`) import `tests/utils/grouped-assertions.js`, equally outside the guard's union — 22 test files / 31 statements in total (two files overlap both groups). The umbrella's "10 src files and 19 test imports" is a drafting-time figure (pre-#432 the tip measured 18 src / 13 test *files*); the guard scan — not any count — defines the set, which is why the guard is written first.
- Prune-shape facts: `backend-select.ts` owns not just the credential guard but `ClaudeRunContext` and `scrubCredentialValue` — deleting it forces `RunAgentOptions.claude` out of `agent-runner.ts`, which orphans `claude-spawn-dir.ts`; the `AgentBackend` knob's closure importers are `backend-select.ts` (co-deleted in the prune's first move) and `agent-runner`/`agent-command` (whose knob imports die in the branch deletions), so once the deletions land the knob has no closure importer and `config.ts` is orphaned — its only other closure edge is `worktree.ts`'s `detectGitRoot`, so `worktree` then has zero closure importers. `modelFor` (`afk-runner/src/config.ts`) already returns the ladder-resolved `config.model` for every role (`DEFAULT_MODEL = 'opencode'`); the only per-CLI model mapping anywhere is claude-argv's `modelIdForCli`.
- Test-port facts: every closure module has a test in `tests/review-loop/` except that `progress-log.test.ts` is a `runReviewLoop` integration test importing non-closure modules (`loop-controller`, `run-state`, `issue-ledger`, `build-checker`) — not portable; `agent-runner.test.ts` imports `issue-schema.js` only as an output-exchange zod schema — replaceable with a local minimal schema. `tests/mutation-improve/diff-guard.test.ts` ports alongside its module. Seven closure tests use `tests/review-loop/test-helpers.ts` (`makeTempDir`/`cleanupTempDirs` plus claude fixtures and a worker-pool fake only the non-portable tests need).
- The review-loop originals keep every papai-internal consumer (review-loop's own `cli`/`worker-pool`/`build-checker`; mutation-improve's `cost`/`worktree`/`live-format`/`run-stats`/`agent-runner` imports) — the copy is one-way and papai's tools are untouched.

N/A for this change: chat tool surface / capability or `tool_prefs` gating (no papai tool is touched; runner-agent MCP gating is #432's delivered permission-map boundary, carried verbatim — papai's capability gating neither gates nor is consulted for runner spawns); scope-model ids (no persisted papai state — runner state lives in untracked `.afk-runner/` workdirs inside *target* repos; the `model` key and `AFK_RUNNER_MODEL` are per-invocation runner config outside papai's scope model); drizzle/DB (none).

## Goals / Non-Goals

**Goals:**

- A guard, owned by the runner's own suite, that pins the boundary permanently: nothing under `afk-runner/src` or `tests/afk-runner` imports outside the runner's trees.
- A behavior-identical owned backend, proven inside papai's full gate suite before any history splits (umbrella D5).
- An opencode-only backend reached by extract-by-deletion, with the BREAKING shape documented exactly as the spec states it and golden real-run fixtures green throughout.
- The #432 seam (`opencodeEnv` threading, `composeConfigContent`/`composeChildEnv`) carried through verbatim.

**Non-Goals:** (beyond proposal.md's list — design-level boundaries)

- No re-homing, renaming, or editing of the review-loop/mutation-improve originals or their consumers; no rename of the copied modules during the copy.
- No new dependency: `p-limit` is a declaration of an existing runtime fact (already imported by `afk-runner/src/accounting.ts`, `serve/load.ts`, `work/review-agents.ts` via root hoisting), not an introduction.
- No toolchain/config work: `afk-runner`'s lint/format scripts and tsconfig `include` already cover the new paths; knip ignores the workspace; the mutation ratchet already gates `afk-runner/src/**` by path prefix.
- No pruning of backend-neutral review-loop surface (e.g. `slotKey`/`commitOnDispose` live-rendering options afk-runner itself doesn't pass): the prune deletes the claude plane, not everything the runner happens not to use.

## Decisions

### D1 — Copy shape: verbatim flat copy into `afk-runner/src/agent-backend/`

The 18 closure files and `diff-guard.ts` copy byte-for-byte (SPDX headers included — re-headering is Phase C's license sweep) into a new `agent-backend/` subdirectory, module filenames unchanged. The subdirectory is required, not cosmetic: `afk-runner/src` already owns a `config.ts` and a family of `agent-*` modules, so a flat merge collides; the subdir also keeps the impl↔test mirror mapping intact for the write hook and the mutation ratchet (D7) and makes the copy reviewable as one directory diff. Alternatives rejected: renaming modules during the copy (destroys diff-reviewability and invites silent drift); a shared workspace package (umbrella D1 already rejected — it would make the generic runner depend on papai).

### D2 — The guard: a self-contained scan, staged red→green, no allowlist ever

`tests/afk-runner/no-upward-imports.test.ts` walks every `.ts`/`.mts`/`.cts`/`.js`/`.mjs`/`.cjs`/`.jsx`/`.tsx` file under `afk-runner/src` and `tests/afk-runner` (skipping `node_modules`) — the full set of extensions the runtime can load, not `.ts` alone, since the guard is the artifact meant to outlive the strict-TS convention — extracts import specifiers with a plain regex over `import … from '…'`, `export … from '…'`, bare `import '…'`, dynamic `import('…')`, and CommonJS `require('…')` (with `.cjs` walked, the require form is loadable, so the enumeration covers it) — type-only imports included — and fails naming each offending file and specifier whenever a relative specifier resolves (via `path.resolve` against the importing file, roots from `import.meta.dir`) outside the union `afk-runner/ ∪ tests/afk-runner/`. The regex must not be line-anchored: oxfmt wraps long import clauses (`import {\n…\n} from '…'` exists in both roots today, e.g. `tests/afk-runner/work/agent-layer.test.ts`), so the pattern spans newlines between the clause and its `from` — an under-matching regex is the one hole that silently defeats a permanent fence. `node:`-prefixed and bare specifiers pass the fence leg unexamined; a second leg asserts every bare specifier imported under `afk-runner/src` is declared in `afk-runner/package.json` (package name extracted from the specifier, checked against dependencies — today's red run names `p-limit`), giving the spec's stands-alone requirement an in-run verifier instead of waiting for Phase B's isolated install. The union, not `afk-runner/` alone, is the fence: tests must reach `afk-runner/src` and each other (`fixtures/fake-pipeline.ts`), and the union is exactly what Phase B renames into one repo root — after the split the fence and the repo boundary coincide.

Why regex and not the repo's AST seam: the guard lives under the roots it polices, so it may import nothing from papai — `src/ts-ast/source-parser.ts` would itself be an upward import, and `oxc-parser` would become a new declared dependency of a tree that must stand alone; import statements in this tree are uniformly formatter-owned, so a statement-level regex has no precision gap that matters. A commented-out import line that matches the pattern fails the guard — acceptable and arguably desirable; the remedy is deleting the stale text, and no suppression mechanism exists by design.

Staging (resolves the ordering tension between "written red first" and "the tree is green after every task"): task 1.1 lands the guard's final assertion body, verifies the red run — it fails listing today's 20 src + 22 test offenders (the 17 review-loop/mutation-improve test files plus the 7 grouped-assertions importers) and the undeclared `p-limit` — and then parks the test under an explicit skip marker naming task 1.3 as its unblock. Task 1.2's suite run stays green while the violation (afk-runner's own upward imports) still exists by design; task 1.3's final act removes the skip and the guard goes green over the same body that was red. The guard never grows a violation allowlist: a guard that can be configured to tolerate today's sins pins nothing.

### D3 — The rewire: specifier replacement only; declare `p-limit`

Task 1.3 rewrites each upward import to the owned backend at the importing file's depth (`../../review-loop/src/agent-runner.js` → `../../afk-runner/src/agent-backend/agent-runner.js`, `../../../…` for `work/`/`drive/`/`graph/`/`fixtures/`, `../../mutation-improve/src/diff-guard.js` → `../../afk-runner/src/agent-backend/diff-guard.js`) — no signature or call-site changes anywhere. The test tree's 7 `tests/utils/grouped-assertions.js` imports are inside the fence's scope but outside its union, so without a disposition the guard stays red at 1.3's verification: `tests/utils/grouped-assertions.ts` (31 lines, zero imports — `assertEach`/`Row`) is copied into `tests/afk-runner/grouped-assertions.ts` alongside 1.2's test-tree copies (copy, not move — papai's own tests keep the original), and its 7 importers rewire in 1.3 like any other upward specifier; with the helper inside the union, the D2 claim that the union is exactly what Phase B renames into one repo root holds. `p-limit` is declared in `afk-runner/package.json` at the root's pin (`^7.3.2`), satisfying the spec's own-declaration requirement: the runner already imports it bare, and today it resolves only through papai's root hoisting — invisible debt the guard concept makes explicit. No existing papai stack alternative covers concurrency limiting; this is a declaration, not a new package. The declaration is followed by `bun install` committing the regenerated `bun.lock`: the lockfile records afk-runner's dependencies block, CI installs with `--frozen-lockfile`, and every in-run gate stays green through root hoisting — the lockfile commit is the only step that keeps the manifest change from failing PR-time installs. (The ported tests' own specifiers are not 1.3's to rewire: they are depth-corrected at port time in 1.2, per D4 — from `tests/afk-runner/agent-backend/` depth the originals resolve to nonexistent paths.)

### D4 — Ported tests: mirrored placement, the portable set, a minimal local helper

Ported tests land at `tests/afk-runner/agent-backend/<name>.test.ts` — the mirror of the impl path, which is what the write hook maps and the mutation ratchet measures. The portable set is 17 of the 18 closure tests plus `diff-guard.test.ts` (18 files). Three carve-outs: `progress-log.test.ts` stays in review-loop untouched (it is loop-controller integration over non-closure modules; its ProgressReporter slice is already covered on the runner side by `tests/afk-runner/agent-reporter.test.ts` — the tasks' "where they exist" parenthetical is satisfied by the module's type-only role in the closure); `agent-runner.test.ts`'s two `issue-schema.js` imports — the static `ReviewerIssuesSchema` and the dynamic `FixerResultSchema` inside the invalid-JSON case — are replaced by a local minimal zod schema (the test needs *a* schema for the file-based exchange, not the issue vocabulary; a literal single-import enumeration would leave one upward dynamic import and the guard red); `diff-stats.test.ts`'s `isTestFile` import — `../../.hooks/tdd/test-resolver.mjs`, a repo-root module outside the union, used substantively in the eight-path agreement row — is replaced by inline expected booleans recorded from the resolver at port time (the row pins the recorded classification as a matrix; copying the predicate would invent the second rule the row's title forbids, and dropping the row would lose the coverage). A local `tests/afk-runner/agent-backend/test-helpers.ts` carries only the subset the ported tests use — measured: the six portable helper-importing tests (`agent-runner`, `claude-spawn-dir`, `config`, `line-handler`, `trace-log`, `worktree`) import exactly `makeTempDir` and `cleanupTempDirs`; `silentTrace`/`silentReporter`, the claude-context fixtures, the worker-pool fake, and the renderer capture serve only non-portable tests and stay in review-loop. Claude-path describes and fixtures ride the port verbatim — their deletion is task 1.4's, so the port stays a pure rewire — and the rewire itself is task 1.2's, not 1.3's: each ported file lands with its impl specifiers depth-corrected to the copy and its helper/schema/resolver imports pointed at the local replacements, because from `tests/afk-runner/agent-backend/` depth the original specifiers resolve to nonexistent paths and 1.2's both-suites verify cannot load them unrewired; task 1.3's rewire covers only afk-runner's pre-existing files.

### D5 — The prune: extract-by-deletion to opencode-only

The prune's rule is bounded deletion, in three moves:

1. **Named module deletions**: `claude-argv.ts`, `claude-stream.ts`, `backend-select.ts` (task 1.4's enumeration), plus the zero-importer completion the deletions force — `claude-spawn-dir.ts` (umbrella D1 names it; orphaned because `RunAgentOptions.claude`/`createClaudeSpawnDir` die with `ClaudeRunContext`), then `config.ts` (the `AgentBackend` knob was its only closure import), then `worktree.ts` (its only closure importer was `config.ts`). The 19 copied files become 13 survivors: `agent-runner`, `agent-command`, `spawn`, `progress-log`, `line-handler`, `event-stream`, `cost`, `run-stats`, `todo-capture`, `live-format`, `trace-log`, `diff-stats`, `diff-guard`. Knip ignores the afk-runner workspace, so orphan detection is this checklist enforced by guard + typecheck + full suite, not a tool.
2. **Branch deletions**: in `agent-command` — `claudeCommand`, `claudeChildEnv`, `STRIPPED_ENV_NAMES`, `PROFILE_CREDENTIAL`, `refuseOpencodeRouteKnobs`, `loadClaudeConventions`, `ClaudeSpawnContext`, and the claude-only option fields (`backend`, `claude`, `effort`, `systemPrompt`, `AgentCommand.stdin`); in `line-handler` — the claude decoder injection, the credential-scrub sink, the `credentialValue` threading; in `agent-runner` — the claude branches (spawn-dir creation, decoder re-arm, the exit-0 result-outcome gate, the conventions system prompt, the stderr scrub that is identity on the opencode route) and the `ClaudeSpawnDir`/`ClaudeRunContext` re-exports; in `todo-capture` — the `TodoWrite` alias and its normalization shape (with claude-stream gone, claude tool_use parts never arrive). The `opencodeCommand` branch, `opencodeEnv`, `extraArgs`, and the continuation mapping are untouched.
3. **Constant rehoming**: `MAX_ARG_STRLEN` (131_072) moves from the dying `claude-argv.ts` into its one surviving consumer, `afk-runner/src/agent-config.ts`, value verbatim — #432's size bound and its refusal message are carried, not redesigned; `tests/afk-runner/agent-config.test.ts` re-imports from there and keeps pinning the value and message.

`modelFor` is unchanged in body: it already maps every role to the ladder-resolved `config.model` (`DEFAULT_MODEL = 'opencode'`); the prune deletes the only per-CLI mapping that ever existed (`modelIdForCli`). The BREAKING shape is exactly the spec's: a config naming a claude-API model string directly gets no translation and no fallback — the string reaches `opencode --model` unmodified and its fate is that plane's model resolution through the existing spawn-failure path (U13 audit: no such config exists; the default is `opencode` everywhere).

Deleted ported tests: the four claude-module tests (`backend-select`, `claude-argv`, `claude-stream`, `claude-spawn-dir`) plus the orphaned modules' (`config`, `worktree`) — 6 of the 18 ported files deleted, leaving 12, which matches the 13 survivor modules minus the unported `progress-log` — the claude describes inside `agent-command`/`agent-runner`/`line-handler`/`todo-capture` tests, and the local helper's claude-context fixtures if any accrued (none are carried per D4). The golden fixtures (`tests/afk-runner/fixtures/real/`, replayed by `tests/afk-runner/parity/golden-replay.test.ts`) are opencode transcripts and must stay green through the prune — they are the spec's no-observable-change proof.

### D6 — The seam carries verbatim

The rewire and the prune change import specifiers and delete the claude plane; nothing else. The `runAgent` call shape (`runSpawn`'s options), the #432 `opencodeEnv` threading (`composeConfigContent` → `composeChildEnv` → `RunAgentOptions.opencodeEnv` → the child's replacement env), the `extraArgs`-based `--session` continuation with `noRetry`, the stall-retry/continuation behavior, the session-ledger hooks, usage/cost/cache accounting field shapes — all byte-identical (`afk-runner/src/agent-spawn.ts` changes one import path). Golden replays and the resume-equivalence suites pin this.

### D7 — Gates and hooks: the run's gates are the verification commands; papai's gates are the PR

Per umbrella D7, the spawned agents of the Phase A run carry no papai write-hook pipeline, so each task's red→green discipline lives in its verification commands (guard red run → all-suites green after copy → guard green + typecheck after rewire → fixtures green + typecheck after prune → full gate pass). Merge-time remains papai's full PR suite. Interaction with the standing hook machinery for any *operator* interactive edit later: `afk-runner/src/agent-backend/**` is gateable implementation code under `isGateableImplFile` and maps mirrored to `tests/afk-runner/agent-backend/**` — the ported tests satisfy the pairing from the moment the copy lands, and the guard test itself is pure addition. The one exception is D4's carve-out: `progress-log.ts` ships without a mirrored test, so an operator interactive edit to it is hard-blocked by the TDD hook until a mirrored `tests/afk-runner/agent-backend/progress-log.test.ts` is authored — TDD-by-design in the pre-Phase-B window, and the hook's block message names the missing path, making the remedy mechanical. Mutation ratchet: the copied files are new targets under the already-gated `afk-runner/src` prefix; carrying their ported tests they should measure near their review-loop originals' scores; task 1.5's `test:mutate:changed` over the branch diff seeds baselines, with the ratchet's standing doctrine (dilution WARNs, kill-count regressions fail) applying unchanged. The closing gate runs `check:full`, not a hand-picked command list, so every full-mode leg is exercised in-run: knip ignores the workspace via `knip.config.ts` `ignoreWorkspaces` (verified in-repo); `duplicates`' jscpd gate is 10% of `tests/` and the ported tests add ≈5.7k near-duplicated lines against ≈442k total (~1.3%, exit code 1 = within threshold, passes); `format:check` reaches the copied and rewired files — runner writes carry no hook pipeline, so each task re-formats what it touched; `license-headers` requires SPDX on new files under `tests/` (the byte-identical copies carry theirs; the guard test, the local helper, and the grouped-assertions port add theirs).

## Risks / Trade-offs

- [Copied modules and ported tests drift from originals during the window] → one-way copy, originals authoritative for papai's tools; the window ends at Phase B/C; behavior drift in the copy itself is caught by running all three suites simultaneously green at 1.2 and the golden replays at 1.4.
- [Umbrella's "10 src / 19 test imports" figure misleads a future reader into under-scoping the rewire] → measured figures recorded here (20 src files / 23 statements; 22 test files / 31 statements, the 7 grouped-assertions imports included); the guard's failure output is the authoritative enumeration the day it runs.
- [Skipped-guard window (1.1→1.3) admits a new upward import unnoticed] → the window is two tasks inside one run; activating the guard is 1.3's final act, and the PR suite re-runs it regardless.
- [Guard regex flags a commented-out import line] → fails naming file and specifier; the remedy is deleting the stale text — cheap, and no suppression path exists by design.
- [Prune orphans a module the runner still needs] → the 13-survivor checklist in D5 is the enforcement (knip ignores the workspace); the closure's only afk-runner consumers are the five enumerated imports, all rewired before the prune runs.
- [`MAX_ARG_STRLEN` diverges between papai and the split repo later] → expected severance after Phase B; until then one rehomed constant, its value pinned by the ported refusal-message tests.
- [A run resumes across half-migrated backend code] → excluded by ordering (umbrella D7): the prune is the run's last task and the run completes before any resume; a broken mid-run state rolls back with `git revert` plus runner-state cleanup.

## Migration Plan

One runner run, tasks in order, tree state explicit after each:

1. **1.1** guard lands (red verified, parked under a skip naming 1.3). Verify: the pre-parking red run — `bun test tests/afk-runner/no-upward-imports.test.ts` fails listing today's offenders (D2's staging); the landed state is the parked skip, which exits 0 by design.
2. **1.2** copy: 19 modules into `afk-runner/src/agent-backend/`, 18 ported tests with import specifiers rewired at port time (impl imports depth-corrected to the copy; `test-helpers` to the local subset; the `issue-schema` and `isTestFile` imports to their D4 replacements) + local helper subset + the `grouped-assertions.ts` copy into `tests/afk-runner/`; originals untouched — unrewired, the copied tests' specifiers resolve to nonexistent paths and this step's verify cannot load them. Verify: `bun test tests/afk-runner tests/review-loop tests/mutation-improve` (all three suites green together — the copy, `diff-guard`'s port included, is proven against each original's suite).
3. **1.3** rewire: all upward imports (measured set, D3 — review-loop/mutation-improve specifiers and the 7 grouped-assertions imports) repointed; `p-limit` declared and `bun install` run to commit the regenerated `bun.lock` (CI's `--frozen-lockfile` installs reject a stale lockfile that no in-run gate catches); guard unskipped and green (both legs — fence and manifest). Verify: `bun test tests/afk-runner && bun run typecheck`.
4. **1.4** prune (the run's last task, D7): D5's bounded deletions in modules, branches, constants, and ported tests. Verify: `bun test tests/afk-runner && bun run typecheck` — golden fixtures green, and the deleted type surface (claude-only option fields, `ClaudeSpawnDir`/`ClaudeRunContext` re-exports) orphans no surviving import, per D5's guard + typecheck + full-suite orphan enforcement.
5. **1.5** closing gate pass: `bun run check:full && bun run test:mutate:changed` — the full-mode leg set plus the mutation ratchet (D7 records each leg's expected disposition) — then the U-ledger Phase A record is written to `docs/architecture/afk-runner.md` (proposal.md Impact's docs deliverable; this run's tasks carry no papai write-hook pipeline, so the record is this task's closing act, not a later operator's).

Rollback at any step is `git revert` of that task's commits (umbrella doctrine); nothing here touches persisted state, papai runtime, or the originals. Phase B starts only from this landed green tip (umbrella D5).
