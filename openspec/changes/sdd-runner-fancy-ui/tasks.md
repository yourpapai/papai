# Tasks — sdd-runner-fancy-ui

Order follows design.md's Migration Plan: additive modules first, screens last, each step test-first. Every new module's test exists (failing) before the module lands; every edit to an existing screen extends its existing suite first. The two design Open Questions (exact palette per token, per-screen panel pairing at wide width) are decidable inside their implementation tasks without touching this list.

Atomicity rule: one task = one change that lands and verifies on its own; every task ends with its `Verify:` command. A "red" verify is the TDD step — the new test fails for exactly the stated missing behavior, nothing else. Focused suites run from the repo root via `bun run test <paths>`.
