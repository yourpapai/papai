# Tasks: afk-runner-agent-mcp

Implements `specs/afk-runner-agent-mcp/spec.md` per `design.md` (D1–D7), in the
dependency order of the design's order-of-work. Every task is one atomic
change and one complete red→green cycle: its failing test and its
implementation land together, no task is a test alone, and each task ends with
its verification command passing — the tree is green after every task, not
only after the last. The Write/Edit TDD hook gates `review-loop/src/**` →
`tests/review-loop/**` and `afk-runner/src/**` → `tests/afk-runner/**`; every
write carries the licence header. No task spawns a real `opencode` — the
hermetic lane's I/O guard denies child processes; the one live smoke is task
5.2, operator-run outside the suite.

## 1. review-loop: the `opencodeEnv` option (design D3)

- [x] 1.1 `AgentCommandOptions` gains `opencodeEnv?: Record<string, string>` — the child's entire replacement environment, caller-composed; the builder never reads ambient `process.env`. The opencode branch of `buildAgentCommand` (`review-loop/src/agent-command.ts`) returns it verbatim as `AgentCommand.env`; absent stays `undefined`, so `realSpawn` inherits `process.env` byte-identically. Tests in `tests/review-loop/agent-command.test.ts`: set option → command carries the map verbatim beside today's unchanged argv; absent → no `env` field. Verification: `bun run test tests/review-loop/agent-command.test.ts`.
- [x] 1.2 The claude branch refuses a set `opencodeEnv` with a named `AgentCommandError`, mirroring the existing `extraArgs` refusal — afk-runner threads no claude backend, and a silent ignore would hide an operator mistake. Tests: claude backend + `opencodeEnv` set → refusal naming the knob; claude without it behaves exactly as before. Verification: `bun run test tests/review-loop/agent-command.test.ts`.
- [x] 1.3 `RunAgentOptions` gains the same optional `opencodeEnv` and `attemptRun` (`review-loop/src/agent-runner.ts`) threads it through to `buildAgentCommand`. Tests in `tests/review-loop/agent-runner.test.ts` pin the passthrough on the opencode route and the refusal surfacing on the claude route. Verification: `bun run test tests/review-loop/agent-runner.test.ts`.
- [x] 1.4 `STRIPPED_ENV_NAMES` gains `AGENT_MCP_ROLE_NARROWING` beside `AGENT_MCP_SERVERS` — the list's contract is "the other route's carriers", and the family gained a member. Test: `claudeChildEnv` strips an env source carrying the new name. Verification: `bun run test tests/review-loop/agent-command.test.ts`.

## 2. afk-runner: knob schemas and `resolveAgentMcp` (design D1/D2)

New module `afk-runner/src/mcp-servers.ts` (env-knob seam, not config-ladder logic); tests in the new `tests/afk-runner/mcp-servers.test.ts`.

- [x] 2.1 `AGENT_MCP_SERVERS` base-map parsing, sibling-verbatim in shape: `type: 'local' | 'remote'` discriminates the union (an entry without `type` fails the parse), `z.strictObject` refuses unknown fields, local = non-empty `command` array + optional `environment`, remote = `url` + optional `headers`; names restricted to `[A-Za-z0-9_-]+`; any `oauth` key refused in every spelling; invalid JSON refuses naming the knob; prototype-pollution names (`__proto__`, `constructor`, `prototype`) refused over the raw parsed own keys — the one place the name is still visible before a record-schema rebuild or assignment-style emission silently drops it; blank/unset/`{}` means inactive. Tests: the spec's valid-declaration scenario (one local entry with `command`, one remote entry with `url`, plus a narrowing entry) is accepted; every malformed-value row of the spec's validation scenario refuses naming the offending key and the shape problem. Verification: `bun run test tests/afk-runner/mcp-servers.test.ts`.
- [x] 2.2 `AGENT_MCP_ROLE_NARROWING` parsing plus the shadowing refusals, all in the same parse: role keys validated against the closed `AgentRoleSchema` vocabulary (an unknown key refuses naming it); a narrowing name absent from the base map refuses ("narrowing cannot mint servers") — the narrowing knob is validated in full whatever the base map's state, so a carried name against an unset/blank/`{}` base refuses; intra-map shadowing (base names `A`, `B` where `A + "_"` is a string prefix of `B`, e.g. `foo` beside `foo_bar`) refuses; built-in shadowing (a base name whose `name_` prefix is a prefix of a built-in tool name on record — today `external`, prefix of `external_directory`) refuses, from a recorded-not-guessed reserved-prefix list pinned by its own test. Tests: one row per refusal naming the offender, plus the pinned-list test. Verification: `bun run test tests/afk-runner/mcp-servers.test.ts`.
- [x] 2.3 `resolveAgentMcp(env, model)` — D2's credential-pair matrix, read only when the surface is active (an inactive surface never touches credentials): `<provider>/<model>` + both `LLM_API_KEY` and `LLM_BASE_URL` set → active with the pair; slash-shaped model with either half missing → refuse naming the missing key (half a credential pair is a contradiction); bare model (no `/`, e.g. the `opencode` default) with the pair set → active, no provider facts, warns naming the ignored keys — never their values — and proceeds; bare model with neither set → active, no provider facts. Tests: all four matrix rows plus the inertness row (an inactive surface beside a set pair reads nothing, warns on nothing). Verification: `bun run test tests/afk-runner/mcp-servers.test.ts`.
- [x] 2.4 `mcpFor(surface, role)` — per-spawn resolved set: the base map minus the role's narrowing entry; a role with no narrowing entry carries the full base; narrowing only removes (minting was refused at resolution). Tests: a checking role (reviewer/skeptic) sheds the work servers while un-narrowed roles (drafter/decomposer/atomicity) keep both; a role absent from the narrowing map carries every base server. Verification: `bun run test tests/afk-runner/mcp-servers.test.ts`.

## 3. afk-runner: content composition and serialization (design D2/D3/D4)

New module `afk-runner/src/agent-config.ts` — pure functions over their inputs; the emitted shape is a locally-typed plain JSON object (no `@opencode-ai/sdk` dependency, copy-never-import from the sibling); tests in the new `tests/afk-runner/agent-config.test.ts`.

- [x] 3.1 Provider block and model ref: for a slash ref, the provider id is the first `/`-segment and the model id the remainder (which may itself contain slashes — the sibling's `parseModelRef` rule); the block is the sibling's proven shape copied not imported — `npm: '@ai-sdk/openai-compatible'`, `name: 'OpenAI-compatible'`, `options` carrying `apiKey`/`baseURL` plus `setCacheKey: true` unconditional, and a `models` entry keyed by the model id; the bare-model row emits no provider block at all (fabricating one keyed to a built-in shared provider would same-key-clobber binary-owned configuration). Tests pin both rows' emitted shape. Verification: `bun run test tests/afk-runner/agent-config.test.ts`.
- [x] 3.2 Permission base: exactly one `<name>_*` key per base-map server — `"allow"` for each server in the spawn's resolved set, `"deny"` for each server the role's narrowing sheds — denies emitted before allows (belt-and-braces only; D1's refusals keep the emitted wildcards pairwise disjoint, so no emission order can flip another key's verdict); no `"*"` key, no built-in tool names, `ask` never emitted, no operator-supplied permission text copied (the knob schema has no permission passthrough). Tests: granted/shed composition; an inspection over the emitted permission map finds no `ask` value and no key outside the base map's generated wildcards. Verification: `bun run test tests/afk-runner/agent-config.test.ts`.
- [x] 3.3 `mcp` block and serialization: the resolved set's entries with every remote forced `oauth: false` (parse refuses the key, emission pins it — clean `failed`-with-error degradation instead of a run parked at `needs_auth`); the composed content is exactly `$schema`, `provider` (slash row only), `model` (the same ref the argv carries), `mcp`, `permission` — nothing else: no `agent` profile blocks, no `small_model`, no facts the runner does not hold. Tests assert the emitted document shape end to end for the slash and bare rows, including the absence of every non-MCP key. Verification: `bun run test tests/afk-runner/agent-config.test.ts`.
- [x] 3.4 D1 size bound: the serialized full-base composition (provider block included when active) is measured against `MAX_ARG_STRLEN` — imported from review-loop's `claude-argv.js`, the same constant the over-limit claude system prompt refuses with — and an over-limit map refuses naming `AGENT_MCP_SERVERS` (the alternative is an opaque `E2BIG` at the first spawn); the full base is the upper bound of every per-spawn composition, because narrowing only removes `mcp` entries and swaps `"allow"` keys for the shorter `"deny"`. Tests: an over-limit full-base row refuses with the knob named; the bound is measured on the full base even when the spawn's own resolved set is narrowed. Verification: `bun run test tests/afk-runner/agent-config.test.ts`.

## 4. afk-runner: spawn-seam composition and threading (design D1/D3/D6)

- [x] 4.1 `SpawnedEvent` (`afk-runner/src/agent-noise-schemas.ts`) gains optional `mcp?: readonly string[]`; `AgentLayerDeps` gains the same optional resolved-surface field this task's resolution step reads (absent → inert, so the seam change is green before task 4.3 threads the field from the CLI boundary); `prepareSpawnContext` (`afk-runner/src/agent-layer.ts`) resolves `mcpFor(surface, role)` beside the existing `modelFor` and emits the resolved set's server names on `spawned` where it is emitted today — names only, the honest bounded payload (connection status settles inside the child on the `opencode run` route). Optional and additive: old logs parse unchanged; an absent surface emits no `mcp` field. Tests: an active surface's spawn event carries exactly the resolved names; an absent surface leaves the event byte-identical. Verification: `bun run test tests/afk-runner/agent-noise-schemas.test.ts tests/afk-runner/work/agent-layer.test.ts`.
- [x] 4.2 Per-spawn env composition at the afk-runner layer through a DI'd env source (the one place permitted to read the ambient env): a full replacement map `{ ...envSource, OPENCODE_CONFIG_CONTENT: content }` with the family's four carrier names — `AGENT_MCP_SERVERS`, `AGENT_MCP_ROLE_NARROWING`, `LLM_API_KEY`, `LLM_BASE_URL` — deleted from the copy (replace-never-merge semantics make the deletion free here, and without it per-role narrowing would widen credential exposure instead of narrowing it); an ambient `OPENCODE_CONFIG_CONTENT` is overwritten when the surface is active; an inactive surface composes nothing and threads no `opencodeEnv`, leaving inheritance untouched. The map rides `runSpawn` → `runAgent`'s new `opencodeEnv` option. Tests with an injected env source: carriers stripped from the child env, content set, ambient content overwritten, inactive → no `opencodeEnv` passed and no credential read; no emitted event payload carries the content or any credential value (names, statuses, counts only). Verification: `bun run test tests/afk-runner/work/agent-layer.test.ts`.
- [x] 4.3 Thread the resolved surface as a new optional field on `RunDeps` (`afk-runner/src/run.ts`) → `PipelineWorkDeps` → every `AgentLayerDeps` construction site: the `agentSeamsOf` factory (`afk-runner/src/graph/pipeline-agent.ts:19`), the `agentOf` factory (`afk-runner/src/graph/pipeline-work.ts:103`), and the two review-stage assembly sites that hand-roll agent deps outside them — `reviewModule`'s subset literal (`afk-runner/src/graph/pipeline-work.ts:171`) and `buildReviewScope`'s field-by-field rebuild (`afk-runner/src/work/review.ts:182-187`). Both review sites enumerate fields rather than spread, so an omitted optional field would compile silently and drop the entire review half of a run to contentless spawns — a review-stage spawn (reviewer or skeptic) is therefore explicitly pinned composing content, the pin the compile step and the shape tests cannot otherwise provide. The four sites land together: the review-stage pin passes only when every site threads. Tests: a review-stage spawn's injected `SpawnFn` receives the composed child env; the two factory sites thread likewise. Verification: `bun run test tests/afk-runner/graph tests/afk-runner/work`.
- [x] 4.4 Verb-time wiring in `cli.ts` (`afk-runner/src/cli.ts`): after `resolveRunnerConfig` and before dispatch, the two spawning verbs — `start` and `resume` — additionally resolve `resolveAgentMcp(env, model)` and refuse on any invalid input, naming the offending key and the shape problem, before any run work, any agent spawn, or budget spend; the resolved surface lands on the deps for threading. The non-spawning verbs — `status`, `report`, `stop`, `runs`, `analyze`, `serve`, and the bare run-dir fold summary — skip the MCP step entirely (env knobs are per-invocation and more volatile than the config file; `stop`, the calm-stop channel for a live budget-burning run, must not be lost to an unrelated MCP typo). Tests: an invalid knob fails `start`/`resume` before any spawn or spend, naming the offending key; the same invalid knob leaves `stop`/`status`/`report`/`runs`/`analyze`/`serve` ungated; a valid surface on `start` reaches the spawned child's replacement env end to end (hermetic — the injected spawn seam observes it, no real `opencode` runs). Verification: `bun run test tests/afk-runner/cli.test.ts tests/afk-runner/cli-stop.test.ts`.

## 5. Docs and live smoke (design D6/D7, migration plan)

- [x] 5.1 Document the surface in `docs/architecture/afk-runner.md`: the two knobs and the credential-pair matrix; the refusal catalogue (alphabet, prototype-pollution names, both shadowing classes, role vocabulary, minting, oauth, the size bound); the gating boundary — runner-agent MCP calls are gated solely by the delivered permission maps, papai's capability gating and per-context `tool_prefs` neither gate nor are consulted (runner spawns carry no papai context; a runner agent consuming a papai-hosted server authenticates by binding token and bypasses per-context resolution); runner-level keying with nothing persisted anywhere; and the residuals stated plainly: the model-readable content exposure (S3-9 class — direct operators to prefer servers needing no credential in the content until the named containment follow-up), the resume-drift interaction (resume a run under the same knobs it started with), the wholesale replacement of any ambient `OPENCODE_CONFIG_CONTENT` when the surface activates, the carrier-name strip reaching declared local server commands' inherited environment (a value a server command needs must ride its entry's `environment`), the dead-entry boot tax (a dead server costs up to the binary's 30 s bound per spawn, and every spawn boots its own instance, so the tax multiplies by the run's six-plus spawns), and the discovered-only name-prefix-collision residual. Verification: docs are oxfmt-ignored, so the floor is the spec's documentation requirements made greppable — `rg -n 'AGENT_MCP_SERVERS|AGENT_MCP_ROLE_NARROWING|LLM_API_KEY|binding token|same knobs|30 s' docs/architecture/afk-runner.md` returns a hit for every mandated term.
