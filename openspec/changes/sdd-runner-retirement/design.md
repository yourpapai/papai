## Context

See `proposal.md` — Why. R1–R4 are delivered and archived-eligible; the R4 cut-over (`openspec/changes/sdd-runner-cutover/`) flipped every operator entry point to afk-runner and handed this change the deletion list explicitly (its Non-goals). The retirement gate is the U-ledger's falsifiable trigger set (U9, `openspec/changes/v1-live-proof/reflection.md`): a live run needing sdd-runner-only behavior; a parity-oracle regression; a deletion surface that depends on sdd-runner code something still reads. Exploration (this change's starting point) fired only the third: `opencode-agent/src/model-metadata.ts` imports `sdd-runner/src/pricing.js`, with two test-side importers. The parity oracle is self-contained — `afk-runner/src/legacy-fold.ts` and `tests/afk-runner/fixtures/**` never read `sdd-runner/` — so deletion cannot break it structurally.

Scope model: no new persisted state anywhere; dev tooling, workdir-local, no DB, no chat surface, no capability/tool-prefs surface.

## Goals / Non-Goals

Goals: delete the frozen workspace with every live reference resolved or removed; perform the re-tighten the workspace's existence justified; retire the sdd-named main specs with an honest coverage mapping; leave one clean revert point.

Non-Goals (design-level): re-homing live behavior into afk capabilities (the afk delta stack's archive step); renaming the `.sdd-runner` workdir or afk provenance comments (D6); porting observe mode / audit verb / any TUI surface (declined, U8-adjacent); C8; U5 enforcement.

## Decisions

### D1 — `pricing.ts` re-homes to `opencode-agent/src/`, its sole consumer

The models.dev client (206 lines; deps: zod + node builtins only) and its 339-line test move verbatim; the three importers repoint from `../../sdd-runner/src/pricing.js` to local paths; `opencode-agent/CLAUDE.md`'s documented boundary ("revisit at a third consumer") resolves by consumer-count collapse — the import crosses no workspace boundary anymore. Alternatives: promoting to root `src/` (speculative — `src/model-context.ts` is a candidate consumer, not a consumer); parking in `afk-runner/` (it has no pricing DB by design — cost rides `event.usage.costUsd`); a new shared workspace (ceremony for one consumer). No behavior change; `MODELS_DEV_URL` pinning test moves with the file.

### D2 — The deletion is one atomic commit; the whole alias family dies together

`sdd-runner/` + `tests/sdd-runner/`, the workspaces entry, and all five `sdd-runner:*` aliases (including the R4 cut-over alias `sdd-runner:start`) land in a single commit. R4's split existed so the frozen workspace's hygiene gates stayed runnable while it existed; with the workspace gone the family is dead weight. Rollback story changes shape deliberately: `git revert <R5>` replaces the one-line manifest revert. Alternative: keeping `sdd-runner:start` as a permanent alias — rejected, it is the transitional alias R4 named this change to delete.

### D3 — The re-tighten is performed, evidence-first

`scripts/detect-duplicates.ts`'s ignore block is removed in full, then `duplicates` runs and whatever surfaces is adjudicated per pair. The block mixed two species: parity-pairing ignores (ported substrate tests vs their `tests/sdd-runner/` sources — the pairing dies with D2) and frozen-corpus ignores (`**/tests/afk-runner/fixtures/**` — the fixtures stay forever, and `fixtures/fake-pipeline.ts` inside is real code). Any ignore that must survive gets re-justified in place as frozen-data, never as parity. This follows the C7 precedent (honest split, no performed re-tighten): if new duplication surfaces, it is deduplicated or consciously re-ignored with its own comment — not waved through on the old block's authority.

### D4 — `GENERATED by sdd-runner` headers reword; frozen bytes stay frozen

`afk-runner/src/work/materialize.ts`'s two header strings and the `auto-sdd` schema/template strings switch to the surviving producer's name. No hash covers `decisions.md`/`assumptions.md` (the gate hashes sidecar covers the gate file), and the only pins are two assertions in `tests/afk-runner/work/materialize.test.ts` — updated test-first (the file is under `afk-runner/src/**`, so the TDD hook gates the edit). Historical fixtures keep their bytes: they are frozen run artifacts, not living output.

### D5 — Main-spec retirement by removal-only deltas; the mapping is the migration

Each of the four `sdd-runner-*` capabilities is emptied via `## REMOVED Requirements` with Reason + Migration pointing at the unarchived afk delta that governs the behavior now, the process canon (`docs/architecture/sdd-pipeline.md`, canonical process sections), or — for observe mode, the audit verb, and the TUI surface — a recorded decline. Nothing is re-homed into new capabilities in this change: the afk stack's own archive steps create the durable homes, and duplicating requirements under new names now would fork the truth. Trade-off accepted: until that archive, pipeline behavior is governed by delta specs plus the canon doc, not by main specs.

### D6 — Names that stay: `.sdd-runner` workdir, provenance comments, frozen fixtures

The config default `workDir: '.sdd-runner'` keeps its value: renaming orphans every existing run directory, the run-index, and the `.gitignore:68` entry — the string is a directory name, not a workspace reference. afk-runner's "copied from sdd-runner" provenance comments stay: they document parity lineage, and git history holds the source after deletion. `tests/afk-runner/fixtures/**` (including the historical `state.json`s that mention sdd-runner) stays byte-frozen — it is the oracle corpus.

## Risks / Trade-offs

- [Re-tighten surfaces masked duplication beyond cheap fixes] → D3's per-pair adjudication; a fix that would grow beyond dedup or a conscious re-ignore gets brought back to the change rather than silently re-widened.
- [`bun.lock` / Dockerfile drift] → lockfile regenerated with `bun install` after the workspaces entry drops; Dockerfile loses both COPY lines; CI's frozen-lockfile install is the verification.
- [In-flight agent branches carry the old `package.json` (the #323 pattern)] → `reconcile-agent-branch-push` covers it, as the cut-over already noted; the drift-refusal names its fields.
- [A reader of `sdd-runner/` escapes the inventory] → the deletion task re-runs the reference search repo-wide as a pre-flight gate, exactly as exploration did; the one known reader is D1.
- [Mutation baseline holds a deleted file's key] → the single `sdd-runner/src/session-create-form.ts` entry is pruned in the same sweep; the ratchet measures existing files only.
- [Spec gap window: retired main specs while afk deltas unarchived] → D5's trade-off; the deltas stay readable under `openspec/changes/`, the canon doc survives, and the ledger notes the archive as the consolidation step.

## Migration Plan

1. D1 pricing move + importer/test repoints + `opencode-agent` doc notes → `opencode-agent` suites green.
2. Deletion sweep (D2): workspaces entry + aliases, `sdd-runner/` + `tests/sdd-runner/`, Dockerfile, knip, coverage-map branch + baseline key, `check.sh` comment, `bun install` → typecheck/lint/knip green.
3. Re-tighten (D3): drop the ignore block, run `duplicates`, adjudicate surfaced pairs.
4. Naming honesty (D4): materialize headers test-first, schema/template strings.
5. Docs + ledger: CLAUDE.md rows, `afk-runner.md` (U9 → delivered, relaxation window closed, retirement paragraph past tense), `sdd-pipeline.md` banner, `commands.md` scope line, CHANGELOG.
6. Full verification: `bun check:full` (parity and memo oracles inside the sweep), Dockerfile-affecting CI green.

Rollback: `git revert` of the deletion commit restores the workspace, aliases, and lockfile in one step (the R4 one-line revert is superseded, not extended).
