# Design: v1-live-proof

> Post-run record: [`reflection.md`](reflection.md) — pass-criteria verdict per D3, the pre-registered
> findings adjudicated, incident observations, and the U-ledger re-score (exactly one `next`: U9).

## Context

See proposal.md — Why. C1–C6 shipped the graph kernel, think-half, gates, tail, and failure recovery, all proven against the 26-fixture corpus and in-process drills. The engine has never run live: real `opencode` spawns through `typedSpawn(realSpawn)`, real wall clock, real budget, a human answering gates. C7 is simultaneously the live proof, the reflection that re-scores the U-ledger, and the close-out of the C1–C7 relaxation window (`docs/architecture/afk-runner.md` §Prototype relaxation window). Empirical grounding established during exploration: five historical M-depth runs show 10–12 spawns, median 4–10m wall per spawn (max 20m), $3.4–7.6 at mid-tier pricing, and 2.7–3.8-day spans on gate waits; token volumes are fixture-faithful (`costUsd` is 0 — history ran free-tier models).

## Goals / Non-goals

Goals: a falsifiable proof definition executed live; harvested live evidence in the corpus; an evidence-forced ledger re-score; an honest relaxation close-out. Non-goals beyond proposal.md: no engine behavior changes — if the live run exposes a bug, the run records it and the fix is a follow-up change, not a mid-proof edit (only a crash-shaped bug that blocks completing the run at all may be fixed, with the deviation recorded in the reflection).

## Decisions

**D1 — Two runs, honestly classified.** An S calibration run (docs-shaped change — the classifier's honest-S space) proves plumbing before the M proof run (a fresh, genuinely-wanted single-module code change). No `--depth` override: classification is part of what's proven; divergence is a reflection input. Alternatives declined: a single S run (docs-only exercises the least of the pipeline); an L run (the parked residuals all honestly classify L — migrations/auth/provider — the most expensive shape); an override (falsifies the depth event's `source`).

**D2 — Targets chosen; runner from branch, target master.** *S calibration*: actualize README and project docs for the GitHub task-tracker plugin — master ships the plugin but its README sells only Kaneo/YouTrack and the docs map misses it. *M proof*: the plugin tool-gate port (delete the hardcoded ACP tool-name set in the orchestrator's who-may-use filter; plugins declare `gate: 'operator'`; a `ToolGateRegistry` port drives the filter) — genuinely wanted (a standing layering violation), contained, cross-module, honestly M. The existing `openspec/changes/plugin-core-separation-toolgate/` folder on master is the human-authored **rubric**: the run scaffolds its own change from a collision-free task-file H1 (slug `operator-tool-gates-via-registry`), and the original folder stays untouched as the grading reference. Task texts are vetted against the prescreen L-keywords before `start` — phrased "task-tracker plugin" / "operator tool gating via a registry port", never the L-words; expected prescreen: S and M respectively. If the proof run still classifies L, that is a recorded finding and a re-pick — the designated fallback is mutation-floor hardening of one or two uncovered valuable modules (the ratchet covers 170/990 `src` files; uncovered: analytics, chat, src-root), which is classifier-honest M. The runner executes from this worktree; the target is a fresh worktree off master via the five-key `repoRoot` (copies, not imports — the target needs nothing from this branch; both targets' ground already lives on master).

**D3 — Pass criteria (falsifiable).** (a) Zero operator hacks: events appended only by the runner; operator writes only gate answers/steer. (b) Incidents recover through documented verbs only (`resume`, gate settle). (c) The produced change passes `openspec validate --strict` and its tests in the target. (d) Memo/report honesty spot-checked against the folded log. (e) The reflection names ≥3 concrete frictions — zero frictions means the reflection failed, not the engine.

**D4 — Incident plan.** *Kill drill (primary, D6 window):* telescope = `tail -f events.ndjson` until `round_open` + `spawned` (L1), then kill the holder.json pid **and its process group**; expect same-round resume continuing the in-flight session (`latestInFlight` → `resumeSession`); the orphaned agent child's behavior (settles? re-attached? output lands mid-recovery?) is a pre-registered live unknown, observed and recorded. *Veto at the final gate on a converged round 1:* exercises outcome-ordered settle (answered→exit→mover), veto-updater revision, the deliberate over-cap round (`startRound: current+1, cap: round.cap`), severity flow-through or a re-presented early-style gate. Expected 2 operator settles (3 if the revision leaves blockers/materials). *Incident C (scratch run, bogus model):* launches-fails → not a transport failure → watchdog retries burn → `AgentValidationError` → `stage_failed{kind: exhausted}` → budget re-run → escalation → abort → `failed` memo. Pre-registered: the kind is `exhausted` (agent-level), not `infra` (transport-only) — the taxonomy boundary is itself a reflection observation. The missing-binary variant (true `SpawnError{infra}`) stays a one-line fallback. Unaimable windows (W4, the sub-second D7/W7 gaps) are recorded as accepted, fixture-proven.

**D5 — Five keys from data.** `budget: 15` at mid-tier models (≈2× the priciest historical M run, covering incident re-runs) or the default 5 on the free tier — `zai-coding-plan/glm-5.3` has fixture precedent; `deadline`: unset (attended run; per-spawn walls proven sufficient — max historical 20m vs the compiled 30m cap); `workDir: .sdd-runner` default; `repoRoot`: the fresh target worktree. Expected attended span ~3–4h.

**D6 — Live corpus lane.** The M run's log joins `tests/afk-runner/fixtures/` in a live-marked lane (vocabulary parallel to synthetic-marking). Oracle: `memoFieldsOf(fold(log))` equals the memo the run persisted + per-line schema validation; agent noise (L0) is already tolerated by `toKernelEvent` skipping. Ported-test expectations are untouched — the lane is new, not rewritten.

**D7 — Reflection form.** Per U-item: verdict ∈ {next, rise, hold, fall, park, retire}; evidence citing run artifacts for every non-park verdict (park may cite absence); a falsifiable re-opening trigger. Exactly one `next` or an explicit tie note. Preamble: n=1 live run, verdicts provisional. The re-scored living table moves to `docs/architecture/afk-runner.md` (the archived afk-runner change's design.md is history, not home); the current pointer there is updated. Header notes the U4 symmetry: the form is the prototype output schema an automated reflection state would emit.

**D8 — Pre-registered findings** (decided before the run, so the reflection cannot retrofit): (1) prescreen substring over-match — `authorization` hits the `auth` L-keyword; the regex is a faithful copy of sdd-runner's frozen original (fix deferred, post-C7); (2) honest-S ≈ docs-only — the classifier's conservative max makes S unreachable for real code work; (3) gate-wait calendar dominance — already visible in historical spans; (4) cache economics of session continuation — 53.8M cached vs 4.85M fresh tokens across five M fixtures; (5) orphaned-child behavior at kill. The reflection may add findings; it may not silently drop these.

**D9 — Relaxation close-out, split.** Re-tighten now (oxlint quartet): split the four over-limit files (`run.ts` 603, `gate-waiter.ts` 351, `agent-layer.ts` 314, `event-schemas.ts` 303) along their natural seams, deferring the split *shape* to post-reflection input; convert the four StageId `as`-narrowings (`drive/loop.ts` ×3, `drive/failure-budget.ts` ×1) to zod-parse; extract the C6 error-taxonomy classes to their own module — satisfying `max-classes-per-file` **by extraction, not suppression**, preserving C6's co-location intent at the seam while ending the rule conflict. The two machine-setup assertions (xstate `{} as T` idiom) remain as the documented exception with the design note already recorded in afk-runner's C1 design. Re-time to U9 (recorded at the relaxation site): the jscpd oracle ignores (ported tests mirror sdd-runner — the duplication *is* the parity oracle) and the tests-side `no-unsafe-*` block (tsgolint cannot resolve xstate-inferred types cross-module; the 17 hits are documented false positives). A performed re-tighten of these would immediately need re-loosening — dishonest ceremony, declined.

**D10 — Ordering and hooks.** Run → reflect → re-tighten. The relaxations are lint-config only (zero behavioral difference), so the proof runs the real engine; and the reflection is the right input to the re-tighten (a 603-line orchestrator may deserve thinning, not mechanical splitting). TDD write hooks gate every `afk-runner/src/**` edit — the re-tighten work is behavior-preserving refactor under existing colocated suites (no new behavior to test-first); the live-lane oracle test lands with the harvest; `.oxlintrc.json` and `scripts/detect-duplicates.ts` are config, outside hook scope.

## Risks / Trade-offs

- [The M run misclassifies L despite task-text vetting] → recorded finding + re-pick per D2; the proof is delayed, not invalidated.
- [Kill drill orphans a child that corrupts recovery expectations] → process-group kill per D4; whatever happens is recorded evidence; C6's in-process drills bound the damage (torn tail tolerated, resume-equivalence proven).
- [Free-tier model unavailable on the day] → budget 15 covers mid-tier; model choice is a pre-flight key, not a design commitment.
- [Review doesn't converge; early-gate cap-hit instead] → a legitimate outcome, not a failure — the early gate is part of the graph; the veto incident then rides the early gate with the same richness.
- [Live log contains prompts/task text] → repo-local run dirs (existing convention); the runner never logs tokens/keys by design; harvest review is part of the task.

## Migration plan

None — no runtime surface changes; refactors are behavior-preserving under existing suites. Rollback = revert the splits/re-tighten commits; the harvested lane and reflection are additive artifacts.

## Open questions

- The exact watchdog retry count on a failed-exit (vs stall) spawn in incident C — live-observable, recorded as evidence; no design dependency.
- Whether the calibration run's classification stays S on the chosen docs target — resolved at pre-flight by the same keyword vetting as D2; divergence is a finding.
