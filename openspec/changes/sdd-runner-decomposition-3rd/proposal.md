## Intended behaviour change

Composite runs become operable end to end: routing descends into a gate-pending child, gate listing and sole-candidate routing see plan gates and child runs, a decompose-stage `needs_split` report converts the run into a parent (current change re-scoped to child #1, siblings via the plan gate), live views and reports render the run tree with repriced subtree costs, and the plan gate is decidable from the interactive TUI. Single-change runs — their non-TTY bytes, gate files, and event lines — stay byte-identical where the part-1/2 pins and the frozen non-TTY contract require.
