# afk-runner

The `afk-runner/` workspace is the graph-kernel re-host of the SDD pipeline: lifecycle states, transitions, and guards declared as **data** over XState v5 used purely as a reducer, with machine state derived exclusively by folding the append-only `events.ndjson`. Since C3 the graph **drives live think-half runs** (intake → draft → review) through a generic, stage-agnostic loop — resume is the same loop re-folding the log. Since C4 a presented gate is **machine state** (`gate.awaiting`): four settle producers answer through one validated seam, and the run continues per outcome — approve, extend, veto, or abort. Since C5 the **tail runs to finals**: decompose/atomicity host the final-gate presentation as their last work act, settles are outcome-ordered, finals park terminally with a `completed`/`aborted` memo, the passive `report` command prints the summary, and the memo is at full field parity with sdd-runner's persisted states. Since C6 **failures are run facts**: a typed taxonomy at three seams declares `stage_failed` bookkeeping, a per-stage retry budget re-runs the bracket under budget and presents an escalation gate (mode `escalation`, riding the C4 stack) over it, the `stop` verb gives operators an event-sourced give-up, every park writes an honest memo (abort-at-escalation memos `failed`), and crash-resilience is proven in-process — torn-tail tolerance, the prefix property, and resume-equivalence drills. It exists beside `sdd-runner/` (which stays frozen until a retirement change), not inside it; work modules are copies, never imports. Planning artifacts for the whole C1–C7 effort live in `openspec/changes/afk-runner/` (proposal, design, tasks, `specs/afk-runner-kernel/spec.md`); C3's decisions live in `openspec/changes/think-half-on-graph/`; C4's in `openspec/changes/gate-as-state/`; C5's in `openspec/changes/tail-on-graph/`; C6's in `openspec/changes/agent-failed-recovery/`; this page describes the implemented state and the decisions future changes inherit.

## Layout

- `afk-runner/src/legacy-fold.ts` — substrate Tier 1, the **frozen parity oracle** (sdd-runner's `replay.ts`). Ported test expectations are never rewritten.
- `afk-runner/src/kernel/` — `machine.ts` (setup() registry + pure `initialStep`/`step` wrapping `initialTransition`/`transition`, full derived-state context with the root-level bookkeeping vocabulary `kernelRootHandlers`, scratch tally included), `interpreter.ts` (closed action vocabulary), `fold.ts` (`toKernelEvent` + deterministic fold with mapped/tolerated accounting; `foldLogOrInitial` tolerates a not-yet-created log).
- `afk-runner/src/graph/` — pipeline v0 as per-state data modules (`states/pipeline-states.ts`) composed in `pipeline.ts`; `pipeline-work.ts` composes the per-state **work modules** (work kind + outcome→successor data, context-pure outcome readers) into the `workFor` registry the loop consumes. Since C4 `gate` is compound — `awaiting` is the positional park of a presented gate; review carries the interstitial `gate.presented` edge (no stage-map writes) and awaiting's exits are the legacy mover events. Since C5 the tail declares work: `decompose` (depth-aware — on S its final act presents the final gate) and `atomicity` (always presents) carry the run from convergence to the final-gate park.
- `afk-runner/src/drive/` — `loop.ts` (the generic successor-or-park drive loop; names no stage; compound positions flatten to dot-paths — `gate.awaiting`; self-successors re-run a state's own work, the extended-round path; a done snapshot or an unknown position parks `final`; since C6 the bracket catch declares classified failures — `stage_failed` appended, exit skipped, under-budget self re-run or escalation park), `boundary.ts` (append boundary: pure transition probe, refusal throws), `failure-budget.ts` (C6: `STAGE_FAILURE_BUDGET` compiled constant, the `declaredFailureOf` typed-error classifier, the pure `escalationOwed`/`escalationStageOf` checks), `resume.ts` (resume derivation as pure functions of folded context + session ledger; owed-mover recovery with C5 map-signal gating plus C6 escalation rows, owed-presentation recovery for the W3 crash window, owed escalation-presentation recovery for W5/W6).

## Engine truth model (decision A→D)

Four variants were compared for where authoritative run state lives:

| | A. Pure fold | B. Persisted snapshot | C. Artifacts as truth | D. A + snapshot memo |
|---|---|---|---|---|
| Crash resume | re-fold events | restore snapshot | re-derive from files | memo hit or re-fold |
| Graph evolution | soft (event schema is the contract) | hard (structural coupling) | soft | soft — mismatch ⇒ re-fold |
| Audit | total | opaque internals | only what artifacts record | total |
| Ephemeral state | in events | in snapshot | **absent** | in events |
| Conformance testing | golden replay | hard | partial | golden replay |

**Decision: A now, D when measured.** The log is the write-ahead log; the machine is a projection. XState v5's `transition()`/`initialTransition()` are pure and actor-free — used strictly as a reducer (no actors, no invoked services, no snapshot persistence in V1). Persisted snapshots are structurally coupled to the machine and restart invocations on restore — disqualified as truth. A memo layer (D) is a follow-up (U7) keyed by `(event count, machine version hash)`; a mismatched memo is discarded and re-folded, so no snapshot migrations ever exist.

## Engine loop (live since C3)

Async validation cannot live in guards (guards are sync/pure). Validation is **pre-event at the edge**; the log records only validated transitions; guards are cheap sync re-checks:

```
DRIVE LOOP (generic, stage-agnostic) — fold → workFor(position) → outcome→successor data
        · bracket: append enter (boundary-validated) · run work · append exit
        · successor-or-park: enter the successor iff it declares work, else park
        · parked reasons are data: final · gate-pending · stopped
EDGE-WORK (async, expensive)   agents · Zod checks · openspec validate · file predicates
        │ validated result → append (the only write, through the append boundary)
        ▼
events.ndjson  (append-only, schema-versioned — the truth; state.json is a derived memo)
        │ every append (and on boot: whole log)
        ▼
PURE FOLD   state' = transition(machine, state, event)
        · root-level target-less assigns own all bookkeeping (depth, rounds, tally,
          gate, auto-decisions, children); enters are the only position-movers
        ▼
RESUME = the same loop: re-fold, parked reason from context, re-entry via the
          graph's own self-loop, continuation from the session ledger
```

The action vocabulary is closed (`emit` / `schedule`); the interpreter is the only place the graph causes effects, and replay never dispatches (assigns land in `nextSnapshot.context` and never appear in the executable action array). The `schedule` action stays **dormant by design**: its natural first consumer — reacting to a gate presentation the moment it appends — cannot work through replay (a crash-restart re-folds the log without dispatching actions, so watcher startup needs a resume-path mechanism regardless), and C4's foreground waiter (a run-level post-park continuation in `run.ts`) subsumes it for this consumer as vocabulary, not obligation.

### Gate lifecycle since C4 (design D1–D8 in `openspec/changes/gate-as-state/design.md`)

A presented gate parks the run **positionally** in `gate.awaiting` — the drive loop sees the flattened dot-path, `workFor('gate.awaiting')` declares no work and parks `gate-pending`; the review outcome reader only parks cap-hit on an *unanswered* gate (an answered gate releases continuation — the extend path never clears the record). Every settle — TUI-shape answers, a hand-edited gate file, deadline expiry, the autonomy ladder — funnels through **one seam**: render → parse-back → artifact-integrity check (hashes sidecar) → `gate answered` with explicit `outcome` → the outcome's mover event (`round_open` for extend, `stage_enter(decompose)` for approve-early, `stage_enter(draft)` for veto; abort appends nothing and reaches `aborted` by graph edge). Historical answered events carry no outcome: they park awaiting settlement and **heal forward** — the next settle appends an explicit-outcome event; a mover missing after an explicit outcome is appended by resume (owed-mover recovery). The foreground waiter (1s poll: gate file with a 3-tick stability guard, `steer.md` with extend-at-final rejected, external settlement, deadline expiry under an exclusive `expiry-claim` with one re-arm) settles and re-drives; claims serialize concurrent settlers (`gate-<n>.settle-claim`, legacy `expiry-claim` honored). The ladder always logs (`auto_decision`, rule none included) and settles R1/R2 through the seam. Deadlines are log-truth, thin and config-gated: `presented` stamps `deadlineAt` only when configured.

### Tail lifecycle since C5 (design D1–D9 in `openspec/changes/tail-on-graph/design.md`)

A converged review now runs the tail as graph-hosted work: `decompose` (decomposer agent writes tasks.md, strict-validate retry ×2, halt on double failure), then `atomicity` on M/L (split/merge rewrite; depth S skips the stage entirely — the `decompose → gate` edge carries the S run straight to the final gate). The final gate is presented by the tail's last work module as its final act — files first, then `stage_enter(gate)`, `presented` at max-version+1, the always-logging ladder — and the module's bracket-closing exit lands from `gate.awaiting`. Settlement at a final gate is outcome-ordered (D3): approve appends the gate exit before the answer so the completed edge fires on the answer; extend/veto answer first (the reshaped guard blocks completion while the gate stage is active), then exit, then the mover; abort answers alone and reaches `aborted` by edge. Extended rounds after a final-gate extend re-run the tail as fresh brackets and re-present at v+1. The completed edge's guard is `gate done && no active stages` (S runs keep `atomicity` forever pending); resume heals the W3 window (crash between gate entry and presentation) by appending the owed `presented` at the file-scan version and re-running the ladder, and owed movers are map-gated so a landed extend never re-opens a phantom round. Finals end the run cleanly: a done snapshot parks `final`, the memo writes `completed`/`aborted` (releasing the session id), resume-of-terminal prints the report pointer, and `afk-runner report <runId> [--pr]` prints the passive summary. The memo reaches full field parity with sdd-runner's persisted `state.json`s — proven by the D7 oracle over the surviving originals.

### Failure lifecycle since C6 (design D1–D11 in `openspec/changes/agent-failed-recovery/design.md`)

Failures are declared, typed at three seams: work modules throw `StageHaltError` (kind `exhausted` after 2-attempt strict-validation, `precondition` for structural gaps like a missing tasks.md), the agent layer's schema-validation exhaustion throws `AgentValidationError`, and the CLI's `typedSpawn(realSpawn)` seam rejects launch failures as `SpawnError` (infra). Everything untyped stays crash-shaped — a work-module bug keeps refusal-alarm semantics; only declared failure is a run fact. The drive bracket catch appends root-level `stage_failed {stage, kind, reason, resumeHint?}` bookkeeping (the stage map is untouched — the bracket stays open, the stage still owes work) and consults one pure check, `escalationOwed(context, stage)`: a per-stage consecutive ledger (`failures`/`failureKinds` context residue, cleared by the stage's exit) past the compiled `STAGE_FAILURE_BUDGET = 1` — one free retry per bracket — with `precondition` escalating immediately. Under budget the bracket re-runs in place through the self-successor mechanics (no re-enter, no gate); over budget the loop's escalation presenter renders `gate-<v>.md` (failure ledger, resume hint, budget math, spend) file-first, appends `gate presented {mode:'escalation'}` — the presented event itself is the position mover, interstitial like review's cap-hit, the failed stage stays active — and runs the always-logging ladder: rule `R5` (the reserved rung) when spend is over the ceiling or unknown (extend suppressed from the rendered gate), else rule none. Escalation settles through the same seam: approve and extend both re-enter the failed stage through a fresh bracket (exit clears the ledger, enter re-activates — keeping the pure budget check sound), abort answers alone and reaches `aborted` with the memo recording `failed` — the dormant status finally means *the agent couldn't do the job*. Steer answers it (`extend`/`abort` valid, veto not offered); deadline expiry inherits the standard path (no conservative branch exists, re-arm once, pending). The `stop` verb is the operator give-up: a live owner gets the calm-stop marker (the machinery's first producer, honored at the next boundary), a gate-pending run points at `steer abort`, and a dead run appends `run_abort {reason:'operator'}` — a per-state transitions mixin reaches `aborted` from every non-final state — writes the terminal memo, and releases the session id. Crash resilience is proven in-process: `readEvents` tolerates exactly one malformed final line (torn tail = an interrupted append; interior corruption stays a hard error), every event-prefix of every fixture folds to a legal state with a parked/drivable verdict, and resuming a deterministic run from any prefix converges to the same terminal and memo; resume heals the escalation windows — W5/W6 (files present/absent) re-present the owed escalation at the file-scan version or fresh-render, W7 appends the owed exit+enter mover targeting the still-active failed stage.

### Append boundary and refusal semantics (D5)

Every `stage_enter` append is probed with the pure `transition()`: a snapshot returned **identical by reference with zero executable actions** means no edge fired — nothing appends and the refusal throws at the edge, naming the refused event. The log records only validated transitions; a refusal is a work-module bug, not a run fact (declared failures are C6's `stage_failed` bookkeeping — appended by the loop catch, never by a refused mover). Non-enter events are root-level bookkeeping and append directly.

## Kernel shape (corpus-grounded)

- **The machine owns all derived state.** The full legacy `ReplayState` — stage map, depth, round, per-round digests with last verdict, gate record, auto-decision records, children — is machine context; the parity harness compares every field against `legacy-fold` over all 26 fixtures with bisect-to-first-divergent-event, making it a conformance test of the graph — any guard stricter than the corpus fails parity. The finding→convergence tally lives in context as a scratch accumulator (the only non-projected field besides the gate/failure residues; parity compares the `ReplayState`-shaped fields, never the residue).
- **Root-level target-less handlers own all bookkeeping** (`kernelRootHandlers`): legacy handling is position-independent, and root handlers fire from any state including finals, so out-of-place and post-final events land exactly as legacy folds them. `gate.answered` is answered by both the gate-state edge and the root fallback, mirroring legacy's position-independent answer.
- **Enters are the only position-movers.** Structured `{ type: 'stage.enter', stage }` events with parameterized `isStage` guards per edge; one shared `closeThenActivate` assign; the review self-loop is corpus-real and is the resume re-entry path.
- **Two-layer tolerance:** unmapped event types (L0 noise, …) are skipped by `toKernelEvent`; mapped-but-edge-less events are native xstate no-ops. Either way the fold never errors.
- v0 edge set `start→intake→draft→review(self-loop)→decompose→atomicity→gate`, guarded `gate→completed` on `gate.answered` + map-all-done, `aborted` declared shape-only — simulation-verified over all 14 fixtures with exact parity before implementation. `gate.presented` records into context; its settlement producers are C4. C4 made `gate` compound (`awaiting` initial; mover/abort edges from awaiting; re-presentation re-enters), added the explicit `outcome` on answered events and the `gateDeadlineAt`/`gateOutcome`/re-arm residues (non-projected, parity-excluded like the tally), and grew the corpus to 15 fixtures (the synthetic veto scenario). C5 grew the edge set to `decompose→gate` (depth-S tail) plus re-entry self-loops on decompose/atomicity/intake, reshaped the completed guard to `gate done && no active stages` (guard-equivalent over every historical answered), and grew the corpus to 21 fixtures (the five tail scenarios; the S fixture was the red seed for the edge). C6 added the escalation presented edges on intake/draft/decompose/atomicity, the awaiting retry movers (`stage.enter` to review/atomicity/intake), the `run_abort → aborted` per-state mixin, the `failures`/`failureKinds` residues, and grew the corpus to 26 fixtures (the five failure scenarios; the approve fixture was the red seed for the awaiting→review mover).
- XState is pinned **exact `5.25.0`**: 5.32.6 regressed named-action param inference (`tsc`-visible).

## Grow-not-restore porting strategy

Neither port-as-is nor simplify-and-restore: V1's graph is the current pipeline's shape re-expressed as a graph (parity needs historical logs), so every graph-shape feature (self-loop, parked substate, cross-cutting recovery, back-edges, finals) arrives day one; afk-spike states then land as content on the proven engine. The afk spike (`reports/afk/`, gitignored reference material) is ported by **reimplementation** — importing from a non-repo path would break every other checkout. Deliberate deltas: context stays thin (artifacts live in the change folder), escalation never silent death (budget exhaustion gates), `meta` kept as data. The full afk-state → landing-change table is in `openspec/changes/afk-runner/design.md`.
