# afk-runner

The `afk-runner/` workspace is the graph-kernel re-host of the SDD pipeline: lifecycle states, transitions, and guards declared as **data** over XState v5 used purely as a reducer, with machine state derived exclusively by folding the append-only `events.ndjson`. Since C3 the graph **drives live think-half runs** (intake → draft → review) through a generic, stage-agnostic loop — resume is the same loop re-folding the log. Since C4 a presented gate is **machine state** (`gate.awaiting`): four settle producers answer through one validated seam, and the run continues per outcome — approve, extend, veto, or abort. Since C5 the **tail runs to finals**: decompose/atomicity host the final-gate presentation as their last work act, settles are outcome-ordered, finals park terminally with a `completed`/`aborted` memo, the passive `report` command prints the summary, and the memo is at full field parity with sdd-runner's persisted states. Since C6 **failures are run facts**: a typed taxonomy at three seams declares `stage_failed` bookkeeping, a per-stage retry budget re-runs the bracket under budget and presents an escalation gate (mode `escalation`, riding the C4 stack) over it, the `stop` verb gives operators an event-sourced give-up, every park writes an honest memo (abort-at-escalation memos `failed`), and crash-resilience is proven in-process — torn-tail tolerance, the prefix property, and resume-equivalence drills. Since the log-fidelity change the log is **honest on re-entry and resumption**: `round_open` appends only when it changes folded round state (same-round resume, extend re-entry, and escalation retry re-run work without re-opening the round), and every `resume` invocation leaves exactly one classified `resume{path, stage, session?}` event. It was re-homed out of `sdd-runner/`, not inside it; work modules are copies, never imports, and the frozen source workspace was deleted at R5. Since the R4 cut-over (`sdd-runner-cutover`) it is the **primary runner**, and since R5 (`sdd-runner-retirement`) the **only** one: every operator entry point — the `/sdd:auto` wrappers included — routes here, the `sdd-runner:*` alias family is gone with the workspace, and recovery is `git revert` of the deletion commit. Planning artifacts for the whole C1–C7 effort live in `openspec/changes/afk-runner/` (proposal, design, tasks, `specs/afk-runner-kernel/spec.md`); C3's decisions live in `openspec/changes/think-half-on-graph/`; C4's in `openspec/changes/gate-as-state/`; C5's in `openspec/changes/tail-on-graph/`; C6's in `openspec/changes/agent-failed-recovery/`; this page describes the implemented state and the decisions future changes inherit. Spec coverage lives in the umbrella capabilities `afk-runner-{pipeline,autonomy,cli,output}` (born by `afk-runner-spec-home`, which also records the mirror-wave declines) beside the mechanism capabilities of the delivered changes above.

MCP integration for its stage agents — injection surfaces through the one spawn seam, scoping, server catalogue, and the ranked recommendation — is researched in [`afk-runner-mcp-research.md`](afk-runner-mcp-research.md) (issue #403).

## Engine truth model (decision A→D)

Four variants were compared for where authoritative run state lives:

| | A. Pure fold | B. Persisted snapshot | C. Artifacts as truth | D. A + snapshot memo |
|---|---|---|---|---|
| Crash resume | re-fold events | restore snapshot | re-derive from files | memo hit or re-fold |
| Graph evolution | soft (event schema is the contract) | hard (structural coupling) | soft | soft — mismatch ⇒ re-fold |
| Audit | total | opaque internals | only what artifacts record | total |
| Ephemeral state | in events | in snapshot | **absent** | in events |
| Conformance testing | golden replay | hard | partial | golden replay |

**Decision: A now, D when measured.** The log is the write-ahead log; the machine is a projection. XState v5's `transition()`/`initialTransition()` are pure and actor-free — used strictly as a reducer (no actors, no invoked services, no snapshot persistence in V1). Persisted snapshots are structurally coupled to the machine and restart invocations on restore — disqualified as truth. A memo layer (D) is a follow-up (U7) keyed by `(event count, machine version hash)`; a mismatched memo is discarded and re-folded, so no snapshot migrations ever exist.

## Engine loop (live since C3)

Async validation cannot live in guards (guards are sync/pure). Validation is **pre-event at the edge**; the log records only validated transitions; guards are cheap sync re-checks:

```
DRIVE LOOP (generic, stage-agnostic) — fold → workFor(position) → outcome→successor data
        · bracket: append enter (boundary-validated) · run work · append exit
        · successor-or-park: enter the successor iff it declares work, else park
        · parked reasons are data: final · gate-pending · stopped
EDGE-WORK (async, expensive)   agents · Zod checks · openspec validate · file predicates
        │ validated result → append (the only write, through the append boundary)
        ▼
events.ndjson  (append-only, schema-versioned — the truth; state.json is a derived memo)
        │ every append (and on boot: whole log)
        ▼
PURE FOLD   state' = transition(machine, state, event)
        · root-level target-less assigns own all bookkeeping (depth, rounds, tally,
          gate, auto-decisions, children); enters are the only position-movers
        ▼
RESUME = the same loop: re-fold, parked reason from context, re-entry via the
          graph's own self-loop, continuation from the session ledger
```

The action vocabulary is closed (`emit` / `schedule`); the interpreter is the only place the graph causes effects, and replay never dispatches (assigns land in `nextSnapshot.context` and never appear in the executable action array). The `schedule` action stays **dormant by design**: its natural first consumer — reacting to a gate presentation the moment it appends — cannot work through replay (a crash-restart re-folds the log without dispatching actions, so watcher startup needs a resume-path mechanism regardless), and C4's foreground waiter (a run-level post-park continuation in `run.ts`) subsumes it for this consumer as vocabulary, not obligation.

### Gate lifecycle since C4 (design D1–D8 in `openspec/changes/gate-as-state/design.md`; hardened by gate-settle-robustness, D1–D7 in `openspec/changes/gate-settle-robustness/design.md`)

A presented gate parks the run **positionally** in `gate.awaiting` — the drive loop sees the flattened dot-path, `workFor('gate.awaiting')` declares no work and parks `gate-pending`; the review outcome reader only parks cap-hit on an *unanswered* gate (an answered gate releases continuation — the extend path never clears the record). Every settle — TUI-shape answers, a hand-edited gate file, deadline expiry, the autonomy ladder — funnels through **one seam**: render → parse-back → artifact-integrity check (hashes sidecar) → `gate answered` with explicit `outcome` → the outcome's mover event (`round_open` for extend, `stage_enter(decompose)` for approve-early, `stage_enter(draft)` for veto; abort appends nothing and reaches `aborted` by graph edge). Machine renders are **pre-flighted in memory** (D2): the rendered text must parse back as the same decision before the gate file is ever overwritten — a failed producer settle destroys no presentation. The response grammar is **total over gate shapes** (D1): own-line decision directives `APPROVE` and `VETO[: <redirect>]` sit beside `ABORT` and `→ RUN 1 MORE` (precedence: abort → gate-veto, which precedes the required-ack and is rejected at escalation gates → extend → boxes/acks/answers); a zero-signal response — no directive, no box, no answer, no override — is rejected with directive guidance instead of settling an item-less gate as a vacuous approve, and `APPROVE` over an unchecked box is rejected naming the item (boxes stay authoritative for hand edits at item-carrying gates). A settled gate-level veto reaches the revision round as a first-class whole-gate redirect (`VetoUpdaterInput.gateRedirect`, its own prompt section — never a synthetic item id; the veto-updater no-op requires item-vetoes-empty AND no gate veto). Historical answered events carry no outcome: they park awaiting settlement and **heal forward** — the next settle appends an explicit-outcome event; a mover missing after an explicit outcome is appended by resume (owed-mover recovery). Operator-input settle failures are **contained feedback, never waiter death** (D3): parse/integrity/sidecar failures return a rejected result, the waiter writes a sibling `gate-<v>.response-error.md` (carrying the failed digest) plus a stdout line, keeps waiting, and re-attempts only after the gate file's digest changes — an unchanged poisoned file never re-attempts, on the same waiter or a resumed one; producer-lane failures stay crash-shaped. The foreground waiter (1s poll: gate file with a 3-tick stability guard, `steer.md` with extend-at-final rejected, external settlement, deadline expiry with one re-arm) settles and re-drives; claims are **attempt-scoped** (D4): one pid-carried `gate-<n>.settle-claim` held for a single attempt — claim → parse/integrity → append-or-reject → release — with idempotent self-reclaim, dead-pid stealing, and the legacy permanent `expiry-claim` retired (stale files simply stop blocking). The waiter exits external on an already-explicitly-answered gate record (no duplicate-settle storm; a historical no-outcome record still heals forward). Steer grammar (D7): `veto <id>=<redirect>` is an item veto; bare `veto` / `veto <text>` map to the gate-level veto; an unparseable first line is consumed with a warning, never left unexamined. The ladder always logs (`auto_decision`, rule none included; the decision kind widened additively with `pending` for waiter re-arms) and settles R1/R2 through the seam. **R4's cost-unknown branch is metered-only**: `budget: null`, or an explicit `metered: false` (derived from the budget's null-ness when absent), disables exactly that branch — subscription runs whose `costUsd: 0` never reprices to a known figure are bounded by the round cap and the R2 trajectory alone — while the exceedance branch predicates on numeric-ceiling presence, so an explicitly numeric budget is never bypassed by anything; the escalation rung (R5) keeps its unknown-cost suppression unconditionally. The deadline waiter shares the prelude's `evaluateLadder` (metered treatment included, no waiter-side ladder) and every **claimed** expiry outcome appends the standard `auto_decision` event after its write — settle names the deciding rule, re-arm and stay-pending record `none`/`pending` — while lost claims and human settles stay silent, so replay alone distinguishes waiter-settled gates from human-settled ones. Deadlines are log-truth, thin and config-gated: `presented` stamps `deadlineAt` only when configured. The **mid-presentation crash window heals on resume** (D5): a gate presented-unanswered whose presenting stage's closing exit never landed — map-visible for interstitial presenters, log-visible (no exit after the gate enter) for the final-gate tail — gets its owed `stage_exit` appended before parking, so a later approve reaches the completed final.

### Tail lifecycle since C5 (design D1–D9 in `openspec/changes/tail-on-graph/design.md`)

A converged review now runs the tail as graph-hosted work: `decompose` (decomposer agent writes tasks.md, strict-validate retry ×2, halt on double failure), then `atomicity` on M/L (split/merge rewrite; depth S skips the stage entirely — the `decompose → gate` edge carries the S run straight to the final gate). The final gate is presented by the tail's last work module as its final act — files first, then `stage_enter(gate)`, `presented` at max-version+1, the always-logging ladder — and the module's bracket-closing exit lands from `gate.awaiting`. Settlement at a final gate is outcome-ordered (D3): approve appends the gate exit before the answer so the completed edge fires on the answer; extend/veto answer first (the reshaped guard blocks completion while the gate stage is active), then exit, then the mover; abort answers alone and reaches `aborted` by edge. Extended rounds after a final-gate extend re-run the tail as fresh brackets and re-present at v+1. The completed edge's guard is `gate done && no active stages` (S runs keep `atomicity` forever pending); resume heals the W3 window (crash between gate entry and presentation) by appending the owed `presented` at the file-scan version and re-running the ladder, and owed movers are map-gated so a landed extend never re-opens a phantom round. Finals end the run cleanly: a done snapshot parks `final`, the memo writes `completed`/`aborted` (releasing the session id), resume-of-terminal prints the report pointer, and `afk-runner report <runId> [--pr]` prints the passive summary. The memo reaches full field parity with sdd-runner's persisted `state.json`s — proven by the D7 oracle over the surviving originals.

### Failure lifecycle since C6 (design D1–D11 in `openspec/changes/agent-failed-recovery/design.md`)

Failures are declared, typed at three seams: work modules throw `StageHaltError` (kind `exhausted` after 2-attempt strict-validation, `precondition` for structural gaps like a missing tasks.md), the agent layer's schema-validation exhaustion throws `AgentValidationError`, and the CLI's `typedSpawn(realSpawn)` seam rejects launch failures as `SpawnError` (infra). Everything untyped stays crash-shaped — a work-module bug keeps refusal-alarm semantics; only declared failure is a run fact. The drive bracket catch appends root-level `stage_failed {stage, kind, reason, resumeHint?}` bookkeeping (the stage map is untouched — the bracket stays open, the stage still owes work) and consults one pure check, `escalationOwed(context, stage)`: a per-stage consecutive ledger (`failures`/`failureKinds` context residue, cleared by the stage's exit) past the compiled `STAGE_FAILURE_BUDGET = 1` — one free retry per bracket — with `precondition` escalating immediately. Under budget the bracket re-runs in place through the self-successor mechanics (no re-enter, no gate); over budget the loop's escalation presenter renders `gate-<v>.md` (failure ledger, resume hint, budget math, spend) file-first, appends `gate presented {mode:'escalation'}` — the presented event itself is the position mover, interstitial like review's cap-hit, the failed stage stays active — and runs the always-logging ladder: rule `R5` (the reserved rung) when spend is over the ceiling or unknown (extend suppressed from the rendered gate), else rule none. Escalation settles through the same seam: approve and extend both re-enter the failed stage through a fresh bracket (exit clears the ledger, enter re-activates — keeping the pure budget check sound), abort answers alone and reaches `aborted` with the memo recording `failed` — the dormant status finally means *the agent couldn't do the job*. Steer answers it (`extend`/`abort` valid, veto not offered); deadline expiry inherits the standard path (no conservative branch exists, re-arm once, pending). The `stop` verb is the operator give-up: a live owner gets the calm-stop marker (the machinery's first producer, honored at the next boundary), a gate-pending run points at `steer abort`, and a dead run appends `run_abort {reason:'operator'}` — a per-state transitions mixin reaches `aborted` from every non-final state — writes the terminal memo, and releases the session id. Crash resilience is proven in-process: `readEvents` tolerates exactly one malformed final line (torn tail = an interrupted append; interior corruption stays a hard error), every event-prefix of every fixture folds to a legal state with a parked/drivable verdict, and resuming a deterministic run from any prefix converges to the same terminal and memo; resume heals the escalation windows — W5/W6 (files present/absent) re-present the owed escalation at the file-scan version or fresh-render, W7 appends the owed exit+enter mover targeting the still-active failed stage.

### Review convergence since open-vs-raised (design in `openspec/changes/afk-runner-open-vs-raised/design.md`)

Each round is counted twice, because two different questions are asked of it: **raised** — every finding the round recorded, the trajectory's number (R2's burndown window, lens escalation, `review.md`'s per-round verdict) — and **open** — only what a human can settle, the gate's number (R1, R2's eligibility, the never-cut blocker pre-check, cap-hit gating). A resolution is open when the resolver `dismissed` it, when it claims `assumed` with no assumption record carrying that finding's `findingId`, or when it claims `edited` but the change folder is byte-identical to the prior round's `round-hashes-<n>.json` snapshot (`recordRoundDigests` reuses the gate's own hashing over `listAgentArtifacts`; `review.md`/`assumptions.md` stay excluded — the runner rewrites both every round). A round-1 `edited` claim has no prior snapshot and is taken at face value; a sidecar whose assumptions carry no `findingId` at all predates the link and falls back to a round-level check, so pre-change runs resume with no migration.

The verdict is three-valued — `converged` (nothing open above a nitpick, ≤3 open nitpicks), `needs-review` (nothing open, but an edit above a nitpick no reviewer has seen), `open` — and the `convergence` event carries both count sets: `open` is additive and optional, a pre-split log folds it equal to `counts`, and the kernel and legacy folds stamp `open ?? counts` on every `DigestRecord` (`openCountsOf` is the shared reader). The `finding` event's action enum is deliberately not widened.

Cap-hit routing reads the verdict: `converged` and severity-converged cap-hits flow to the tail with no gate; anything open above a nitpick presents the early gate; a `needs-review` cap-hit buys **exactly one** verification round — re-entering the loop at `round_open(n+1, cap+1)`, the extend mover's shape, with the steer seam's re-read cap floored at the verify cap — and then settles by that round's result (an open MATERIAL from the verification round still gates; a second `needs-review` buys nothing). The once-bound is fold-derived: a round already opened above the depth's base cap means the chain spent its round, and routing is never re-entered from its own result. `reviewOutcomeOf` treats a `needs-review` verdict at the base cap as unsettled (a resumed run re-buys the round pre-loop, same shape) and one recorded above the base cap as settled; severity convergence reads the open set, so a pre-change log resumes exactly as before. The budget guard follows R4's metered semantics — unknown cost refuses only on a metered run, a null ceiling never refuses, a projection reaching a numeric ceiling does; a refused round appends `stage_enter decompose` (the approve-early mover's shape, which settles review via the stage map) and **no** `auto_decision`.

Gate rows carry the reviewer's verbatim gap, not the finding id: `readRoundGaps` joins both lens sidecars (reviewer wins duplicate ids; missing sidecars degrade to the identifier), and the shared `sanitizeRowGap` collapses the row to one line, strips a leading `→`, and truncates at 200 — the checkbox grammar anchors on line starts, so raw agent prose must not parse back as a decision. `renderGateAnswers`/`responseFromAnswers` flatten every free-text field for the same reason. Before the ladder evaluates, `gate-integrity.ts` recomputes both count sets from the sidecars against the gate round's convergence record — a drift in either, or an unparseable sidecar, substitutes an open `POLICY-INTEGRITY` BLOCKER (async reads; wrapped in `signalsOf`) so no rule can auto-decide and the gate waits for a human.

### Log fidelity on re-entry and resumption (log-fidelity change, D1–D8 in `openspec/changes/log-fidelity/design.md`)

Event taxonomy drives emission: **state-shaped** events mean transitions and get fold-derived owedness; **fact-shaped** events are timestamped points where idempotency is meaningless. `round_open{round, cap}` is owed iff it changes the folded round state — `roundOpenOwed` compares the round and effective cap against the work-entry fold's round snapshot (`reviewResumeEntry` derives it; it rides `ReviewEntry.foldRound` to `runRound`). Same-round re-entries — resume of an interrupted round, extend re-entry after a settle mover opened the next round, the under-budget escalation retry — re-run the work without re-opening the round; recursion into round n+1 always clears the comparison; a cap amendment on an open round still emits (defensive). Work-shaped events (findings, convergence, `round_close`) are never suppressed — the work genuinely re-happened. Frozen historical logs keep their doubles: `round_open` stays last-write-wins in both folds and duplicate tolerance remains load-bearing for replay. Every `resume` invocation appends exactly one `resume{path, stage, session?}` event in `resumeRun`, immediately after `resumeInputs` (owed recovery complete) and before the parked/drivable branch — so parked-gate and terminal resumes emit too, one per invocation, never deduplicated. `resumeEventOf` classifies from the post-recovery fold + session ledger: `gate.awaiting` and terminals (including runs the resume's own recovery completed through a gate settle) report `artifact-skip, gate`; review splits by round state — never started → `artifact-skip, review`, unrecorded round → `session-continuation` with the ledger's in-flight session id, else a fresh re-run; every other work stage reports `stage-rebuild, <stage>` (a `start` fold boots from intake). The kernel fold counts `resume` as tolerated; the legacy fold replays it as a strict no-op (pinned over the `same-round-resume-honest-synthetic` scenario). **F-A4 — answered live at C8, operator decided FIX — closed by `escalation-retry-session-continuation`**: the recorded hypothesis (same-process escalation
retries consume `killed` ledger sessions as continuations) is **disproven in the continuation direction** —
the C8 scratch drill killed the drafter child four times and every post-kill spawn (watchdog retry,
under-budget re-run, escalation-approve retry) minted a **fresh** opencode session id, the retry prompt is
the plain base prompt (`buildContinuationPrompt` rides only the cross-process resume seam, where
continuation demonstrably works), and the rebuild was softened only by endpoint prefix caching. Evidence in
`openspec/changes/v2-live-proof/reflection.md` (§F-A4). The operator chose **fix** over accept-as-deliberate
(2026-09-02), and `openspec/changes/escalation-retry-session-continuation/` delivered it — **F-A4 is
closed**: stage re-entries through the spawn seam now consult the session ledger's latest id-bearing
`killed` entry for their (label, round) at `runStageAgent` entry and ride the continuation path (precedence
explicit `continueSessionId` > seam lookup > fresh; dangling `spawned` and settled `done` stay fresh; the
intra-bracket schema-validation retry stays fresh by construction), and review-loop's stall retry re-spawns
continuing the line handler's captured session id, backend-mapped at the command builder (`--session`

### Append boundary and refusal semantics (D5)

Every `stage_enter` append is probed with the pure `transition()`: a snapshot returned **identical by reference with zero executable actions** means no edge fired — nothing appends and the refusal throws at the edge, naming the refused event. The log records only validated transitions; a refusal is a work-module bug, not a run fact (declared failures are C6's `stage_failed` bookkeeping — appended by the loop catch, never by a refused mover). Non-enter events are root-level bookkeeping and append directly.

### Intake warns and the agent write guard (operator paper cuts, D1–D4 in `openspec/changes/afk-runner-operator-paper-cuts/design.md`)

Intake's two silent signals are operator warn lines now: `IntakeDeps` carries the optional `stdout` sink (omitted → silent, mirroring `RunDeps.stdout`), wired at `intakeModule` with the `intake: ` prefix onto `RunDeps.stdout`. A `--depth` override returns before both readings (the prescreen and the estimator), so it warns what it discards — `--depth S skips scope estimation — the forced profile sets the review round cap (S: 1) and skips the atomicity stage (decompose presents the final gate)`; an M/L override warns the same line without the tail. The cap is interpolated from `ROUND_CAPS` (`S: 1, M: 3, L: 4` — a number beats a noun for operator judgment) and the tail clause is conditional because a static "S skips atomicity" note on an M/L override would claim a consequence that run does not get; both clauses reuse the umbrella spec's own stage-sequence tail language so warn, spec, and docs stay one vocabulary. A two-level estimator/prescreen split warns `depth readings disagree by two levels (estimator L, prescreen S) — taking the higher` — `IntakeResult.disagreement` stays (the asserted contract of a directly-tested pure function), the warn becomes its consumer, and the depth event field is untouched for fold parity. Warns fire on every intake execution: a mid-intake crash resumed with the same override present re-enters the branch and warns again — one warn per execution, each invocation re-stating its own override cost (the alternative, persisting "already warned", is durable state bought for silence).

The agent write guard in `agent-layer.ts` answers "did the agent write only where it was told" truthfully: the allowed prefix is `openspec/changes/<changeName>/`, threaded from the spawn options with the trailing slash load-bearing — it is what makes a prefix-sharing sibling (`add-thing` vs `add-thing-extra`) a violation — and the violation error names the offending paths **and** the allowed folder. There is **no tree-wide fallback branch**: `RunStageAgentOptions.changeName` is required on every spawn seam and validated by construction (openspec scaffolds the change before any later stage can spawn), so a `changeName === undefined` caller cannot exist; if a spawn seam without a change name ever emerges, re-widen explicitly in that seam's terms and re-pin the guard tests — do not resurrect the silent tree-wide default. The front-door command doc's flag prose is pinned to the parser: the extracted pure `parseStartArgs` must accept every flag `.claude/commands/sdd-auto.md` documents, with its documented value form, and a flag the parsing silently ignores trips the pin.

## Corpus analysis (the `analyze` verb, run-analysis change)

`analyze [workdirs…] [--json]` is the read-only corpus-report surface over retained run artifacts (`analyze-io.ts` → `analyze.ts`/`analyze-gates.ts`/`analyze-findings.ts`/`analyze-truth.ts`/`analyze-usage.ts` → `analyze-corpus.ts`/`analyze-report.ts`). **Read-only by construction, not discipline**: the injected `AnalyzeFs` seam exposes only `readFile`/`readdir`/`stat` (a type-level test pins write members absent), git goes through `readOnlyGit` over `ExecGitFn` admitting only `log`/`ls-tree`, and the invocation never attends, presents, or settles any gate — a gate-pending corpus run completes byte-unchanged. Every metric is a pure query over `foldEvents(pipelineMachine, events)` — the same kernel fold the drive loop uses, never `legacy-fold` (the parity oracle judges the engine, it is not consumed beside it) — joined with sidecars, gate files, the derived memo, openspec state, and git. Metrics report `known` or `unknown-with-reason`, so inherited logs (older event grammars, missing sidecars, pre-field memos) parse to reduced coverage, never errors.

**Metric inventory**: per-run trajectory (folded `perRound`, both count sets), gate forensics (presented→answered latency, never-answered with age, extends by origin, auto-decisions by rule, waiter fingerprints), settle-origin attribution **by emission order** — the prelude emits its settle-kind `auto_decision` *before* the settle seam's `gate answered`, the deadline waiter *after* its write (both producers' order is pinned by tests in their own suites), so per gate version: record-before-answer → policy, record-after → waiter, no record → human; retry taxonomy (stall vs validation per role via the `spawned` join) and stage-failure taxonomy (`stage_failed` by stage/kind); finding lifecycle (`duplicateIdRate` within-round ledger dups, `lensOverlapRate` by normalized gap, `classChurn`, `resolverActionMix`; `concernPersistence` stays `unknown` until `afk-runner-loop-memory` lands `fingerprintOf` — imported then, never copied); **r2 blocking-cause attribution** per cap-hit state (`r2-fired` / `cost-unknown` / `over-ceiling` / legacy `preview` / `trajectory-blocked`), eligibility reading the convergence record's `open` set (raised fallback) while the trajectory strict-decrease reads raised, `needs-review` never enumerating a state; the consistency audit (fold-vs-memo freshness naming diverging fields, answered-without-presented, completed-after-unsuperseded-abort, `.bak` residue, gate files recording decisions with no answered event) with the **era-contamination flag** excluding inherited development-era runs from corpus aggregates; usage per role (`spawned` join) and per round (`round_open` ts-window) with cost rendered as a lower bound plus the unpriced count (no pricing DB — master's reprice seam is deliberately not mirrored); and the ground-truth join per change folder (tasks done/total, folder existence, commit count, main-ref presence) surfacing `stranded-complete` and `merged-unimplemented` sections.

**The `metered` memo field**: one optional boolean on `PersistedRunStateSchema`, threaded through `MemoSeed`/`writeRunMemo` exactly like `repoRoot` (a runtime input riding the seed, persisted from `createRunState` at run birth — never a fold projection). It is what closes the r2 cause table: metered=true + cost-unknown → `cost-unknown`, metered=false + R4 → `over-ceiling` (the cost-unknown branch is unreachable on an unmetered run), and runs whose memo predates the field degrade those states to the metric's reduced-coverage unknown rather than guessing. ## Concern memory (loop-memory change)

The review loop's memory and control key to **normalized gap fingerprints**, not finding counts or verbatim ids. `fingerprintOf` in `work/concern-model.ts` (case-fold → strip non-alphanumeric → stopword-prune → dedup → sort → join; an empty gap groups alone under a `@<round>:<id>` fallback key) is the one identity a concern has across rounds and across lenses — master's compiled constants, confirmed on afk's corpus by the analyzer, not re-derived.

**Merge integrity.** `mergeLensFindings` dedupes the lenses' findings by fingerprint — differently-quoted copies of one concern collapse to a single finding with first-wins content and the most severe class — so both convergence count sets (`raised`, `open`) and the verdict are invariant to how many lenses quoted a gap. Skeptic finding ids are namespaced `S<n>` (the skeptic spawn validates against `SkepticFindingsSidecarSchema`, a per-spawn refine at the call site — mis-namespaced sidecars fail validation and retry through the existing path), and `ResolverOutputSchema` rejects duplicate resolution ids within a round. Together those make the ledger's `(round, id)` join sound.

**The known-concerns digest.** Prior rounds reach the next reviewer prompt as a capped digest — one round-tagged line per concern (`r3 [S1] MATERIAL edited — narrowed gap (seen r1..r3)`), most recent first, at most `LEDGER_DIGEST_MAX = 15` with an overflow note — never the flat round-untagged ledger. `readResolutionsLedger` returns round-tagged entries joined back to their finding gap text; the prompt builders live in `work/review-prompt.ts` (extracted when review-model hit the max-lines edge).

**The thrash end.** `closeRound` persists the cross-round history to `sidecars/concerns.json` (after materialize, before the `round_close` event) and runs `detectConcernThrash`: a raised finding with ≥2 prior resolved/dismissed entries (third strike), or ≥1 prior entry at a different class (oscillation). On thrash the loop stops instead of recursing — the convergence event carries the cluster ids (an additive `concerns` field; pre-change logs fold it as `[]`, the `open ?? counts` playbook) and `ReviewLoopResult` carries `recurringConcerns`. The denial of the verification round is fold-derived in two conjuncts: `owesVerificationRound` requires an empty `concerns` on the last verdict, and `reviewOutcomeOf` settles a thrash-ended `needs-review` as converged (nothing only a human can settle — the final gate shows the unreviewed edits), so a resumed run re-derives both after a crash mid-thrash. Whichever gate follows carries the `### Concern history` section (round-by-round entries under each concern's fingerprint) in both early and final modes — gathered from the sidecar filtered by the folded cluster ids.

**Cross-artifact consistency check.** Every round's merge is appended with a deterministic scan (`work/artifact-consistency.ts`) over the change folder's proposal/design/spec files: seeded decision-term vocabulary (migration strategy, `*60*1000` interval literals, backticked table/column identifiers) rendered differently across artifacts becomes a synthesized `C<n>` MATERIAL finding naming both files and both renderings — no spawn, no tokens. It rides the normal lens→resolver path (injected at the merge point in `review-agents.ts`), carries a fingerprint like any finding, and a disagreement the resolver dismisses twice therefore ends the loop as thrash on the third raise. Scanning `tasks.md` is declined (it is authored at decompose, after review rounds end); vocabulary widening is gated on analyzer dry-run rates.
