# ToolsSection Close-Out Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close all five open `ToolsSection` UX findings, moving `docs/ux-reviews/_BACKLOG.md` from 23 open to 18 open, without adding a visual baseline.

**Architecture:** Tasks are split by *expected pixel impact*, not by finding order. Task 1 bundles the four fixes that cannot move a pixel and runs the visual audit **without re-shooting**, so a green audit is real evidence rather than a tautology. Task 2 makes the one visible change and is the only task permitted to overwrite a baseline — exactly one PNG. Task 3 flips the findings docs and regenerates the backlog.

**Tech Stack:** Svelte 5 (runes), TypeScript (strict, `.js` import extensions), Bun test runner, Playwright + `@crvy/strybk` for Storybook screenshots, oxlint + oxfmt.

**Spec:** [`docs/superpowers/specs/2026-08-04-toolssection-close-out-design.md`](../specs/2026-08-04-toolssection-close-out-design.md)

## Global Constraints

- Statuses in `docs/ux-reviews/*.md` are exactly `open`, `fixed`, `superseded`. **There is no `partial`.** A non-`open` status requires a `- **Resolved:**` line with a real commit hash or the backlog parser fails loud.
- `client/shared/ui/` primitives are **not** modified by this sub-project. Every fix is local to `client/settings/sections/ToolsSection.svelte` or its `<style>` block.
- **No new visual baseline. The audit floor stays 467.**
- Do not edit a pre-existing test to make something pass. (One deliberate, spec-driven exception is spelled out in Task 1 Step 5 — read it there; do not generalise from it.)
- Never `--no-verify`; never add a lint-disable or type-ignore comment.
- Branch `ui-ux-review-01`; **no merge, no push**; PR #212 untouched.
- `docs/ux-reviews/_BACKLOG.md` is generated by `bun run ux:backlog`. **Never hand-edit it.**
- Client tests must be run with `bun run test:client`, **never** `bun test tests/client/...` — `bunfig.toml:8` sets `pathIgnorePatterns` including `tests/client/**`, so the latter silently discovers nothing and reports success.
- `bun shoot` overwrites baselines. Never run it to make a failing audit green.
- Repo formatter is **oxfmt** (`bun run format`), not prettier.
