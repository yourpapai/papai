## Design Decisions You Must Not Re-Litigate

These were settled during brainstorming. Implement them as written.

1. **Client validation mirrors the server and adds exactly one rule.** The server is `id: z.string().min(1)` and a `type` enum (`src/debug/settings/admin/instances-routes.ts:38-49`). The client adds a duplicate-id check because the client already holds the full instance list, while the server currently lets a duplicate reach the database unique constraint and returns an opaque error. **Do not add a slug/format rule** — it would reject ids the API accepts.

2. **When field errors render.** A field error shows only after the operator has touched that field (tracked in a `Set<string>` populated on blur) — with one exception: the duplicate-id error renders as soon as the typed id collides, touched or not. A pristine form must never be pre-reddened, but a doomed id should say so before submit. The Create button is disabled whenever the error map is non-empty, regardless of touched state.

3. **Load errors and action errors are different things.** Today the single `error` variable carries both, which is why the review saw four raw fetch messages joined by `; `. Task 3 splits them: `loadError` (the four GETs failed) renders as `ErrorState` in place of the tables; `error` (a create, apply, stop, or delete failed) stays an inline line above the content. **Do not route action errors into `ErrorState`** — an existing test at `AdminInstancesSection.test.ts:433` asserts a failed create leaves the tables visible with a `.status-error`, and that behaviour is correct.

```ts
// SPDX-License-Identifier: BUSL-1.1
// Copyright (c) 2026 Dmitriy Lazarev
// Use of this software is governed by the Business Source License 1.1.
// See LICENSE in the project root for details.

/**
 * The consumer shows most errors only after a field is touched, but surfaces this one
 * immediately — so it is exported rather than duplicated as a literal at the call site.
 */
export const DUPLICATE_ID_MESSAGE = 'An instance with this id already exists'

/** Per-field failures for the instance create form; an empty object means valid. */
export interface InstanceCreateErrors {
  id?: string
  type?: string
}

export interface InstanceCreateInput {
  id: string
  type: string
  existingIds: readonly string[]
}

/**
 * Mirrors the server's create contract (`id` non-empty, `type` selected) and adds the
 * duplicate check the server can only answer with a database constraint violation.
 */
export function validateInstanceCreate(input: InstanceCreateInput): InstanceCreateErrors {
  const errors: InstanceCreateErrors = {}
  const id = input.id.trim()
  if (id === '') errors.id = 'Required'
  else if (input.existingIds.includes(id)) errors.id = DUPLICATE_ID_MESSAGE
  if (input.type === '') errors.type = 'Required'
  return errors
}
```
